# 内网工具箱开发指南

> 本文档是内网工具箱的架构说明与开发规范，面向后续接入更多内网应用的开发者与 AI 编码助手。
> 改动前请先读完第一、二章；新增应用按第五章示例执行；所有规则延续壹匣（j1toolkit）约定：简体中文注释、最小改动、密钥不入仓、交付完整代码无占位。

## 一、项目定位与架构

### 1.1 定位

内网工具箱是运行在**内网被控机**（银河麒麟 V10 SP1、统信 UOS 20 优先，兼顾 Windows 10+）上的**原生桌面客户端**（Electron + Vue，QQ NT/网易云音乐同路线），一个长期演进的本体外壳，各业务以**应用（插件）**形式接入。界面为现行 **12 页 Vue**：工作台、执行历史、设置 3 页壳层 + 题库搜题、轨迹导出、树障同步、交跨同步、派车同步、学堂刷课、机巡审核、脚本测试 8 个业务/工具页 + 集群 1 个平台页。

> 平台边界：只面向 Windows 10、银河麒麟 V10 SP1、统信 UOS 20 的近期稳定版本（amd64/arm64）。更老的发行版（glibc < 2.28）不保证 Electron 壳可启动，回退源码 CLI 模式。

> 现行唯一正式轨为 Electron + Python；历史 Go 重构轨与相关构建脚本已整体删除，仓内不保留任何构建引用。

首批应用：

| ----------------- | -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

### 1.2 技术选型（已定，勿擅自更换）

**Electron 45.3.0（壳） + Vue 3 + TDesign（界面） + 内置 CPython 3.15.2 独立运行时上的 Python 核心 sidecar（业务）。**

- 桌面壳用 Electron：UI 上限高、跨平台稳、与壹匣同为 Web 技术族（TDesign 组件同源）；壳层负责窗口/托盘/单实例/原生文件对话框、题库搜题的截屏与 OCR、以及自带 Chromium 的离线 PDF 打印
- **业务逻辑全部留在 Python**（`toolkit/`）：SSO 国密登录、请求签名、导出编排、xlsx 契约、U盘挂载、定时链路——这些是已在内网验证的逆向成果，**绝不重写到 JS**
- 壳与核心经 **stdio JSON-RPC** 通信（`toolkit/app.py rpc`）：免端口/令牌，父子进程 1:1 生命周期，PyInstaller 好打包
- **pcd_export 为旧 Python 原语上的原生线程并发，不是 Go 移植**：查询/渲染原语仍是 `vehicle_export.py`、`uvmp.py`、`official_track.py`；`toolkit/apps/pcd_export/parallel.py` 用 `ThreadPoolExecutor` 做有界并行。查询默认 8 路（钳 1..16），渲染默认 4 路（钳 1..16）；查询阶段结束后，派车单渲染、轨迹渲染两个阶段先后执行，每阶段内多单并行；每个渲染槽位独占 client、Session、renderer 与浏览器 profile；主线程按输入顺序收集结果并更新清单/进度；`manifest.json` 并发互斥 + 临时文件原子替换写入；取消时统一关闭渲染器、取消未启动任务，成功收尾清理临时目录（失败保留诊断）
- 题库搜题的截屏/OCR/悬浮窗在 Electron 壳层（`onnxruntime-node` + PP-OCRv4 mobile，推理跑 `worker_threads`）；课程自动学习复用 Playwright 引擎；CDP 渲染自检为纯 Python（`official_track.CdpBrowser` 打开 `data:` 本地页，零网络），不依赖外部导出工作进程
- 官方页面直出：`official_track.CdpBrowser` 用 `--headless=new` + 独立临时 profile + CDP 驱动用户所选/自动探测的浏览器；PDF 包版打印优先用自带 Electron（`UVMP_ELECTRON` 由壳注入），没有时回退用户所选/自动探测浏览器。两条通道分开验证，不互相冒充
- 历史教训：PyQt5 方案（v1.x）因 PyInstaller/Qt DLL 收集与 NSIS 手写脚本编码问题翻车，已废弃

### 1.3 架构图

```
内网工具箱.exe（Electron 45.3.0）
  ├─ 主进程 electron/main.cjs：窗口/托盘/单实例/原生对话框/--print-to-pdf
  │     ├─ core.cjs：spawn resources/core/uvmp-core(.exe) —— stdio JSON-RPC
  │     ├─ window-state.cjs：窗口状态 + 导航/权限/文件选择守卫
  │     └─ 导航守卫：新窗口一律 deny、顶层导航只允许 dist 内页面、禁 webview；权限白名单仅 clipboard-sanitized-write/fullscreen/display-capture
  ├─ preload.cjs：contextBridge 暴露 window.core（call/onEvent/pickFile/pickDirectory/showItem）
  └─ 渲染进程：Vue3 + TDesign 12 页（desktop/src/pages/*）

uvmp-core（Python，PyInstaller console onedir）
  ├─ app.py usb-agent  → U 盘单监听（udev 事件 + 兜底轮询；systemd/计划任务常驻）
  ├─ cluster/          → 节点集群服务（同进程托管：入网审批/心跳/节点表；指令转发后续接入）
  ├─ app.py rpc        → RPC 服务（getConfig/runJob/…，事件主动推送）
  ├─ app.py selfcheck / daily-export / order-export / tree-sync / crossing-sync / run-script
  ├─ usb_protocol.py / usb_agent.py ← 指令/结果契约、挂载状态机、命令认领与结果落盘
  ├─ apps/<id>/backend.py           ← 业务编排（GUI/CLI/RPC/agent 共用同一函数）
  ├─ apps/pcd_export/parallel.py    ← 有界线程并发 / 渲染槽位池
  ├─ selftest.py                    ← 渲染、SSO、CDP 三项环境自检
  ├─ vehicle_export.py / official_track.py（接口/渲染原语）
  └─ course_autoplay_trial.py / defect_review_trial.py / browser_automation.py（课程/机巡审核引擎、受控浏览器辅助）
```

**分层铁律**：`toolkit/` 与 `apps/*/backend.py` 禁止 import 任何 GUI 依赖（无头环境要跑）；Electron/Vue 只做展示与交互。

## 三、运行方式

```bash
# 桌面端开发（需 node 24+；核心用 UVMP_PYTHON 指定解释器，建议 3.15.2）
cd desktop && npm install && UVMP_PYTHON=python3.15 npm run dev

# 核心 CLI（无头场景；冻结版二进制用法相同。测试/开发用 Python 3.15，构建依赖分界 3.10）
python3.15 toolkit/app.py selfcheck                     # 自检：加载全部应用后端
python3.15 toolkit/app.py usb-agent                     # U 盘单监听（常驻）
python3.15 toolkit/app.py usb-agent --once              # 手工检查/执行一轮
python3.15 toolkit/app.py daily-export                  # 本地手动导出（调试）
python3.15 toolkit/app.py order-export --xlsx 清单.xlsx --outdir ./output
python3.15 toolkit/app.py tree-sync                     # 本地手动执行一次 U 盘指令（调试）
python3.15 toolkit/app.py crossing-sync                 # 同上
python3.15 toolkit/app.py run-script 脚本.py -- 参数...  # 脚本测试页同款运行入口
echo '{"id":1,"method":"ping"}' | python3.15 toolkit/app.py rpc   # RPC 冒烟

# 环境自检（设置页「环境自检」卡片）：render / sso / cdp 三种，走任务事件模型
# CDP 自检只打开 data: 本地页（零网络），验证 导航/eval/新tab/截图 PNG/printToPDF
```

> 离线机器须先装依赖（`packaging/requirements-core.txt`，或把 `offline_packages/*.whl` 解压到 `pylib/`）：缺 `requests` / `websocket-client` 时 `daily_sync`、`pcd_export` 后端与部分测试模块会直接导入失败。
> **不再承诺 Python 3.7 源码兜底**：测试与核心按 3.10+ 语法编写（括号化 `with`），`build_on_device.sh` 在低于 3.10 的解释器上只产出旧版兼容核心且课程自动学习不可用。

## 四、插件规范

### 4.1 应用 = 三处落点

1. `toolkit/apps/<id>/app.json`：声明（id/name/badge/desc/order）
2. `toolkit/apps/<id>/backend.py`：业务后端（契约见 4.2，GUI 无关）
3. `desktop/src/pages/<XxxPage.vue>`：界面（并在 `App.vue` 的 `PAGE_MAP` 登记一行）

### 4.2 backend.py（契约）

```python
APP_ID = "my_app"

def run(job, params: dict) -> dict:      # 必需：任务入口；返回业务摘要 dict
def handle_command(job, cmd: dict, mount: str) -> dict:
                                         # 可选：usb-agent 指令入口（cmd 已归一；
                                         # 失败直接抛异常，agent 统一写结果/删指令）
def status(cfg: dict) -> dict:           # 可选：状态卡数据源（RPC getAppStatus）
def preview(params: dict) -> dict:       # 可选：输入预览（RPC preview）
def launch_browser(cfg: dict) -> dict:   # 可选：启动/复用受控浏览器（RPC launchAppBrowser，见 §4.6）
```

`run` 内规范：`job.log()` 逐行汇报；`job.set_progress(cur, total, label)`；工作单元间 `job.check_cancel()`；单条失败不阻塞整体；产出落用户目录，中间件成功后删除。

### 4.3 Vue 页面规范

- 组件用 **tdesign-vue-next**；主题一律走 `src/theme.css` 的 token（政企蓝白：品牌蓝 #0E3DA8 / 页面底 #F5F7FA / 正文 #1D2129 / 边框 #E5E6EB…，与 j1toolkit 双端同套），禁止自定义新色系；特征元素（白卡 12px 圆角轻影、浅蓝底导航图标块、直角警示块）样式已在 theme.css 里。
- 调核心一律走 `src/api.js`：`call(method, params)`；任务用 `runJob(appId, params, {onLog,onProgress,onDone,onError})`（返回 `{jobId, cancel, finished}`；`finished` 可等待旧任务到达终态）。
- 文件/目录选择用原生对话框：`pickFile(filters)` / `pickDirectory(defaultPath)`（别让用户手填路径）；打开产物目录：`call('openPath', {path})`；文件管理器定位：`showItem(path)`。
- 任务结果统一用 `components/TaskResult.vue` + `lib/task-result.mjs`：状态/摘要/产物/折叠排错日志；失败与启动失败自动展开日志并滚入视野。历史记录统一用 `components/HistoryCard.vue` 与 `lib/history.mjs`，参数回填用 `lib/restore-params.mjs`（只回填表单，不自动执行）。
- 12 页由 `App.vue` 的 `PAGE_MAP` 注册并经 `keep-alive` 保留；侧栏、命令面板（`Ctrl+K`）、`Ctrl+,` 进设置均属壳层，页面不自行实现系统全局热键。
- 壳层守卫（改主进程时必须保持）：`window.open`/`target=_blank` 一律 deny；顶层 `will-navigate` 只允许 `dist/` 内页面与开发态精确 origin；`will-attach-webview` 直接拒绝；权限请求与检查走同一白名单（`clipboard-sanitized-write` / `fullscreen` / `display-capture`）。`core:call` 只转发 `RPC_METHODS` 白名单内方法，IPC 仅接受主窗口渲染层来源；`quizSearch:readFile` 只读本窗口文件对话框刚选中的 `.xls/.xlsx/.csv`（realpath 严格比对，登记上限 20 条），不是通用读文件接口。

### 4.4 RPC 方法表（`toolkit/rpc.py` 维护）

`ping` / `getSystemInfo` / `getConfig` / `saveConfig(updates)` / `getApps`（每项含 `has_browser` 标记） /
`getAppStatus(app_id)` / `launchAppBrowser(app_id)` → 启动/复用受控浏览器（仅实现 `launch_browser` 的应用可用；同步调用，不创建 Job） /
`preview(app_id, params)` / `runJob(app_id, params)` → `{job_id}` /
`cancelJob(job_id)` / `getJob(job_id)` / `getActiveJob(app_id, instance_id)` / `getHistory(app_id)` / `openPath(path)`（只允许打开状态目录、任务档案登记的输出目录、配置登记的业务目录、集群已登记安装包与卷标匹配的 U 盘挂载点） /
`getJobLog(job_id)` → `{text, truncated}`（任务完整日志全文；超过 20 万字符只回尾部并置 `truncated`） / `deleteHistory(app_id[, job_id])` → `{records, files, skipped}`（删执行记录：传 job_id 删单条，不传清空该应用，连带任务日志/档案） / `clearLogs()` → `{removed, skipped}` / `getLogStats()` → `{dir, files, bytes}` /
`getDevScriptEnv()` → `{python, version, frozen, config_path, state_dir, encoding}`（脚本测试页显示实际运行环境） / `getUsbAgentStatus()` → `{running, heartbeat, heartbeat_path, log_path}`（`running` 以单实例锁是否被占用判定，`heartbeat` 为 agent 每轮检查落盘的心跳；无 U 盘时也有，用于区分“服务没在跑”与“在跑但 U 盘未挂载/不可读”） /
`getClusterStatus()` → 集群节点状态（本机身份、服务状态、待审批/已入网节点、Worker 心跳） / `getClusterNodes()` → `{nodes, pending}` / `approveClusterNode(node_id)` / `rejectClusterNode(node_id)` → 本机 Hub 审批节点并返回最新状态 /
`clusterStartExport(params)` → `{job_id, total, nodes}`（发起节点切分派车单/轨迹导出；`params.nodes` 为选中节点及各自 `query_workers`/`render_workers`） / `clusterGetExport(job_id)` → `{job, logs, queue}` / `clusterCancelExport(job_id)` → 取消本机发起的集群导出并向在途节点发取消
`clusterListUpdatePackages()` / `clusterAddUpdatePackage({path, platform, arch, version})` / `clusterRemoveUpdatePackage({id})` / `clusterPushUpdate({nodes})` → `{job_id, total, nodes}` / `clusterGetUpdate(job_id)` → `{job, logs}` / `clusterCancelUpdate(job_id)` / `clusterGetPendingUpdate()` → `{pending}` / `clusterOpenPendingUpdate()` → 打开待安装包（手动安装，不自动提权）

集群服务跑在 `usb-agent` 常驻进程内；RPC 子进程经本机 `127.0.0.1:<listen_port>/cluster/admin/*` 读取/审批（只允许本机来源），读不到时回退到 `state/cluster/service.json`、`registry.json`、`peers.json`。节点间请求走 HMAC（见 §六 第 8 条）。

U 盘监听不再由 GUI/OS 定时器逐分钟驱动：`app.py usb-agent` 常驻（systemd 服务 / Windows 登录计划任务），GUI 启动时只补拉一次（flock 单实例）。指令消费、挂载、结果落盘均在 agent 进程内完成，任务历史仍写 `state/history/<app_id>.jsonl`。

事件（核心→壳主动推）：`job.log{job_id,line}`、`job.progress{job_id,current,total,label}`、`job.done{job_id,job}`、`core.exit{code}`。
新增方法 = `rpc.py` 里加一个 `m_<名字>` 方法（自动入表），同步更新本节；壳层还要把方法名加进 `electron/core.cjs` 的 `RPC_METHODS` 白名单，否则 `core:call` 直接拒绝。

> **stdout 是协议独占通道**：`serve()` 启动时把 `sys.stdout` 指向 stderr，业务代码/第三方库的 `print` 只进 stderr；协议行由构造时留存的真实 stdout 写出。核心侧新增日志不要直接写 stdout。
> **任务号格式**：`YYYYmmddHHMMSS-<6 位十六进制随机>`，跨进程唯一；旧的两段式 `-NN` 任务号仍可被 `getJobLog` / `deleteHistory` 读取与删除（统一走 `state.is_job_id`）。
> **配置写回**：`saveConfig` 走 `config.save`——递归类型校验（类型不符返回错误、不落盘）、唯一临时名 + fsync + 原子替换、旧文件损坏先备份 `config.json.corrupt-<时间戳>`、旧文件读不出来时拒绝覆盖；密码类字段留空或 `******` 表示不修改，`getConfig` 不回传任何明文密码（SSO / 机巡及其实例 `params.password` / 集群 `secret`，只回 `has_password` / `secret_set`）。

> 环境自检走 `runJob` 的特殊 app_id：`selftest:render` / `selftest:sso` / `selftest:cdp`，由 `toolkit/selftest.py` 实现，复用同一套 Job 事件与历史，不注册为 `toolkit/apps` 应用。
> `quiz_search` 例外：实时截屏/OCR/悬浮窗不适合 stdio RPC，**不新增核心 RPC**；壳层 IPC 以 `quizSearch:*` 命名（`electron/quizsearch/index.cjs registerIpc`），渲染层经 `window.core.quizSearch.*` 调用。

### 4.5 任务（Job）模型

- **防休眠开关**：`runJob` 参数带 `keep_awake: true` 时，`JobManager` 在任务线程内启停 `toolkit/host_awake.py` 的 `HostAwakeGuard`：Windows 用 `SetThreadExecutionState` 阻止休眠/关屏，Linux 用 `systemd-inhibit`（`start_new_session=True` 独立进程组，停止时按组回收；**禁止 `preexec_fn`**——任务跑在线程里，多线程进程 fork 有死锁风险）+ `xdg-screensaver`/`xset` 定时重置；同时每 30 秒产生一次真实鼠标微动（Windows `mouse_event`；Linux `xdotool`/XTest），避免系统把长时间无操作判为空闲；不勾选时不触碰电源状态。轨迹导出、学堂刷课在启动卡片、机巡审核在实例参数弹层提供「运行时防止关屏/休眠」开关（按应用记忆上次选择）；题库搜题为壳层实时功能，不接这个开关。

- 核心内 `jobs.JobManager` 统一管：日志写 `state/logs/<job_id>.log`，结束写 `state/jobs/<id>.json` + `state/history/<app_id>.jsonl`（页面历史数据源）。
- 内存有界回收：终态 Job 在内存中只保留最近 `MAX_TERMINAL_JOBS = 50` 个（`jobs.py`，超出按 job_id 降序回收内存对象）——防常驻进程内存无限涨；**只收内存对象，任务档案（state/jobs/）与日志文件（state/logs/）不受影响**，`getJobLog` / `getHistory` 仍可查全部历史。
- 日志清理：`app.py` 各入口（rpc/daily-export/order-export 等）启动时 `state.prune_old_logs(30)` 自动删除 30 天前的任务日志/档案；设置页「日志管理」卡显示占用（`getLogStats`）并可一键清除全部（`clearLogs`）；**运行中任务的 `.log`、常驻 `usb-agent.log`、以及无任务档案且 1 小时内有写入的日志一律豁免**（进程崩溃残留的旧日志仍会被清掉），豁免项计入 `skipped`。状态目录 `0700`、状态文件与任务日志 `0600`；历史记录页「日志」按钮经 `getJobLog` 查看单次任务完整日志（超长只回尾部）。
- 执行记录删除：各应用页「最近执行记录」卡统一用 `components/HistoryCard.vue`（新应用接入直接复用即获得删除能力）——单条「删除」与「清空」均走 `deleteHistory`（`state.delete_history_records`）：删 `history/<app_id>.jsonl` 对应行并连带删 `logs/<job_id>.log`、`jobs/<job_id>.json`，app_id/job_id 正则校验防路径穿越，占用文件跳过计数；root 镜像侧的历史不受影响（镜像只追加，不同步删除）。
- 取消钩子：长任务的浏览器/线程池等资源经 `job.add_cancel_hook(fn)` 统一释放，取消后任务进入 `cancelled`，不得留下孤儿浏览器或线程池。
- 状态机：pending → running → success / failed / cancelled；`job.on_done` 在终态落定后触发（RPC 事件时序正确性靠它，勿在业务 finally 里自行推 done）。启动前已取消的任务不执行业务函数，直接落 `cancelled` 并回调；业务抛 `SystemExit`/`KeyboardInterrupt`（`BaseException`）一律落 `failed` 终态，不让线程静默退出、任务永远 `running`；`_finalize` 的档案/历史写入失败不会吞掉 `on_done`，也不影响终态对象回收。

### 4.6 课程自动学习（course_autoplay）应用要点

- **引擎复用，不另起 CDP 实现**：仓根 `course_autoplay_trial.py` 即课程引擎（PyInstaller 以 `--add-data course_autoplay_trial.py` 收编进 `_MEIPASS` 根，backend.py 运行时 importlib 按路径加载）；通用浏览器启动/状态辅助为 `toolkit/browser_automation.py`（Playwright 连本机 CDP，浏览器可执行文件复用 `render.chrome`）。
- **可选后端契约 `launch_browser(cfg)`**：实现它的应用才可被 RPC `launchAppBrowser({app_id})` 调用（`getApps` 以 `has_browser` 标记）。打开浏览器不是 Job、不产生任务档案；已有受控浏览器时直接复用，不重复启动。
- **用户流程**：填启动网址（随 config.json 永久保存）并点「打开浏览器」，自动访问该网址 → 人工登录并打开任意同学堂平台页面契约的「课程设置」列表且置前台 → 勾选「仅扫描（不进入课程）」或点「开始学习」（主按钮只有开始学习，扫描是 checkbox）→ 运行中可点「暂停学习」；完成提醒以点击「开始学习」时的模式为准：启动时为正式学习且本轮无未完成课程（`pending=0`）才弹窗，扫描模式或仍有未完成课程不弹。
- **暂停/检查点语义**：点击暂停立即中断当前等待并释放开始按钮；若旧任务尚未到达终态，再次开始会等待旧任务退出，不与旧任务重叠运行。暂停只断开 Playwright、关闭当前学习弹窗，不杀受控浏览器、不清登录态；暂停回滚当次尝试、不记失败。检查点按 trainid/列表分别持久化到 `state/course-autoplay/checkpoints.json`（续刷页、真实失败次数、已处理数、跳过项及原因）；切到新培训班用独立检查点，切回可恢复。正常完成一轮后 `active=false`，下次开始为新一轮（旧跳过项可重试）。任务历史 `cancelled` 且 `result.paused=true` 显示「已暂停」。日志走 `job.log` / `job.set_progress` / 任务档案，失败截图 `state/logs/<job_id>_failure_*.png`。
- **引擎既有能力保持**：多标签识别、全分页扫描、视频真实 `ended` 等待（拖动后每轮限 30 秒，超时重新定位播放器并重拖，连续 3 轮失败交回单课重试）与学习记录上报确认、非视频课件加载、单课 3 次（`course_autoplay.max_attempts`）后跳过继续、末页后从第 1 页从头复核、刷新后直接跳回续刷页。
- **「可学习」判定口径**：只有 `courseStatus=1`、`coursetype=1`（网页课程）、`coursespace≠2`（非「仅支持 APP 学习」）且 `contenttype≠3` 的课程才计为可学习并参与进度统计；`hour ≥ 100` 视为已完成。列表里没有任何可学习课程时（`studiable=0`）只记「不能判定为学习完成」，不误报成功；仍有未完成课程时按 `未完成：第 N 页《课程》当前 x%` 逐条列出并附跳过原因。完成弹窗只在启动模式为正式学习且本轮无未完成课程时出现。
- **检查点稳健性**：`checkpoints.json` 读取时逐字段清洗（`attempts` 归整为非负整数、`last_progress` 只保留有限浮点、`skipped_ids` 去重排序、`resume_page` 至少为 1），旧版残留的脏值不会让整轮任务起不来；写入走线程锁 + 文件锁 + 原子替换，同进程并发落盘不会丢其他培训班的条目。
- **配置**（`config.py DEFAULTS` 与 `config.example.json` 同步）：`browser_automation{cdp_url 默认 http://127.0.0.1:9222（仅本机回环）、profile_dir 空=state/browser-automation/profile/port-<CDP 端口>（按端点隔离，避免多应用/多实例共用一套登录态；业务传入的显式目录原样使用）、start_url 空=空白页（填写后永久保存并自动访问）、step_timeout=120}`、`course_autoplay{max_attempts=3}`。已连上 CDP 时启动网址只放在「已同源页签（仅前置）→ 空白页 → 新页签」，绝不覆盖用户当前页签；`launch` 自己拉起的浏览器在 CDP 超时或启动网址失败时按进程组回收整棵树。
- **多开实例**：页面顶部「实例」标签，每个实例独立 `start_url`、`cdp_url`、profile、参数与 Job；同应用不同实例可并行，接口按 `instance_id` 隔离，每实例独立日志/进度。

### 4.7 机巡审核（defect_review）

- **引擎复用**：`defect_review_trial.py` 为审核引擎，PyInstaller 以 `--add-data defect_review_trial.py` 收编到 `_MEIPASS` 根；backend 用 importlib 按路径加载。
- **流程分层**：① 登录流程：重启浏览器只打开配置根地址（不带路径）→ 等应用自动跳 `/login` → 自动登录（失败无限重试）→ 进入缺陷识别任务页，流程结束；② 筛选流程：逐项下拉直点选项 → 点查询 → 等列表出现，流程结束；③ 审核流程：点「进入」→ 逐图审核。刷新/重启只作为兜底：先刷新网页，仍失败再重启浏览器并回到①，不混入主流程。
- **流程**：页面按实例填启动网址、登录账号/密码、任务状态、作业性质、电压等级、线路名称、起止日期、输出目录、任务名称跳过表、单图超时/重试、未审核数阈值、卡死检测、任务后刷新阈值（任务数/图片数）、是否无视缺陷框 → 「启动」或「全部启动」自动启动/复用实例浏览器并自动登录 → **脚本自己进入「智能分析 → 智能识别 → 缺陷识别任务」**。作业性质、电压等级、线路名称可留空；留空时脚本不点击/不清空对应筛选项，填完任务状态和日期直接查询，不做该项筛选。任务状态和起止日期仍必填。
- **自动登录（唯一模式）**：不再提供人工登录开关，账号/密码/启动网址始终必填；每个实例有独立账号/密码，持久化到本机 `toolkit/config.json`（600）的该实例参数中；不同实例可用不同账号。启动网址可只填站点根地址（不带路径），由系统自动跳转 `/login`；脚本只被动识别登录页，不主动拼接登录地址；登录页与任务页（`/intelligentAnalysis/identification/IdentifyTasks`）不是同一路由，只有看到任务列表或系统菜单才判定为已登录；应用已落在 `/login` 或已渲染系统菜单时只等待被动跳转，**不再重复导航启动网址**；浏览器重启/打开根地址后，先等登录页密码框和至少两个输入框渲染完成（最多 15 秒），期间不填表；只有 `about:blank` 空白页，或既无登录表单也无系统菜单的 404/深链接错误页，才回一次配置的启动网址恢复应用。登录成功后先等应用自动跳到 `/home` 并渲染菜单；进任务页优先走**前端路由**（history 模式 `pushState` + `popstate`，hash 模式改 `location.hash`），避免整页深链接概率 404；前端路由未渲染出列表才用 `goto(..., wait_until="commit")` 整页直达（不等 DOMContentLoaded，站点可能长期停在资源加载 mask）。出现 404/错误页时优先点应用自己的「返回首页」或顶部「首页」（前端路由，不整页 reload），点不到才回启动网址；该检测不只在进任务页时执行：登录循环、重启浏览器打开默认页、等待任务列表、刷新恢复轮询中，只要页面同时出现「404」和「返回首页」且两者相邻，都先点一次返回首页再继续登录/导航；仅出现 404 数字（如首页统计）不再误判，带「智能分析/统计报表」菜单的首页/任务页即使残留 404 提示也不按整页 404 处理。直接打开任务页改为 location.assign 后轮询任务列表，不再等 Playwright 导航生命周期；任务页已加载时直接跳过导航，前端路由/打开启动网址等待失败后只要任务页筛选栏已可见，也按已加载继续，不再回退菜单；筛选项展开只认当前控件 aria-expanded，页面残留其它下拉不会阻止当前筛选点击；再走「智能分析 → 智能识别 → 缺陷识别任务」菜单，菜单失败重试一次（2026-11-10 现场 404 修复）。任务列表识别兼容 iframe 内表格，并用「任务名称 + 任务状态 + 查询/重置」文案兜底 Avue/Element 结构差异。自动启动浏览器时即使打开启动网址超时，也只记日志并继续连接现有页面，不阻断后续登录。验证码由随包 `electron/ocr/common.onnx`（ddddocr common，MIT）离线识别，不访问互联网；登录表单出现后先填账号密码，再在最多 8 秒内轮询验证码，避免图片晚加载时被过早刷新；DOM 取像素失败（跨域图片/canvas 污染、验证码在 shadow DOM/改 canvas 渲染）时按 locator 找验证码元素直接取原图（页面 fetch/data/blob 或 `canvas.toDataURL`，保持原始分辨率，不做屏幕截图），显示尺寸被 CSS 缩小（如 130x48 显示成 23x9）也按 `naturalWidth/naturalHeight` 取像素，日志出现「验证码像素改用原图」即走该路径；原图也取不到才记「验证码诊断」并刷新；识别成功统一大写填入，登录页没有验证码输入框时按无验证码登录。登录失败没有重试上限，验证码/页面异常会刷新后继续，账号错误逐步退避但不会自行停止；登录成功后自动进缺陷识别任务。掉登录、页面 OOM/崩溃或浏览器重启后同样自动登录并回到任务页。登录表单识别失败时每轮只保存一次 `failure_XX_login_page.png` 现场图，便于核对登录页结构。
- **OOM/卡死恢复**：任务边界不再每个任务都刷新页面，而是按「任务后刷新阈值」监测累计任务数和累计图片数；默认 10 个任务或 200 张图片（任一达到即刷新），两个阈值都设 0 表示不自动刷新。未到阈值只记 `任务后监控：累计 N 个任务/M 张图片…` 并继续，避免频繁重载导致筛选/导航卡死。刷新或浏览器重启后计数清零；重启受控浏览器只打开用户配置的根地址（不带任何路径），避免直开带路径 404，404 统一由「返回首页」兜底；看门狗超过「卡死检测」秒数无任何日志/进度时，通过 CDP 关闭当前实例浏览器，重新启动、自动登录并回任务列表（看门狗只持任务对象弱引用，且每轮检查后释放线程局部引用，任务对象释放后自动退出，避免遗留线程长期占住页面对象）；页面 `crash` 事件立即触发重启。恢复只针对当前实例的 CDP/profile，不影响其他实例。浏览器关闭后的登录恢复依赖上述自动登录。浏览器窗口按多实例数量自动排布：1 个全屏，2～3 个水平排列，4 个 2×2 十字，更多按网格；页面顶部用状态标签展示各实例是否在正常运行，实例卡片显示各自进度、阶段与启停/参数/日志/删除操作。
- **立即健康重启**：连续慢图达到阈值且当前任务界面未审核数超过「立即重启未审核阈值」时，不等待任务边界，立即重启当前实例浏览器、自动登录并重入任务；该阈值为 0 时退回任务边界重启。健康重启有 5 分钟冷却。
- **自动启动**：实例浏览器未运行时，开始审核会先自动启动该实例浏览器并打开启动网址，无需手动打开浏览器。
- **超时与健康阈值**：单步等待、动作超时、页面跳转超时、登录结果超时、验证码识别超时、单图等待、卡死检测、慢操作阈值/连续次数、立即重启未审核阈值均按实例保存在 `params`，随实例切换；不再只读全局 `browser_automation.step_timeout`。
- **筛选下拉与查询**：下拉优先直接展开点选项，不先填字段（线路也先读选项再点，忽略「全部/请选择」占位）；选项为空时自动收起/重新展开最多 6 次，每次等 0.5 秒；在全部可见下拉里查找选项，避免 .last 命中空下拉；下拉文本读取加 0.5 秒上限，避免 Playwright 默认 30 秒等待挂起导航；首次进任务页列表未查询或查询无数据都算正常：筛选栏「任务状态」+「查询/重置」出现即视为页面就绪，查询返回空列表按“没有可审核任务”结束，不判页面加载失败；接口有记录时最多等 15 秒让表格行渲染，避免系统卡时误判空表或直接刷新；下拉优先原生长按点击 `.el-select__wrapper`；线路过滤输入优先 `input.el-select__input`，避免写隐藏 input；多实例窗口过窄时页面视口自动提升到至少 1280×900，布局不再被压成“22...”。只有选项未渲染时才用 JS 输入过滤兜底。展开时按 Element Plus 的 `.el-select__wrapper` / `.el-select__selection` / `.el-select__input-wrapper` 等内部节点 DOM click；都点不开时保留一次 1.5 秒短超时原生 click 兜底（唯一例外）。线路输入框直接 JS 赋值并触发 input/change，避免整页导航期间 fill 等 5 秒；每次设置筛选项都写日志，设置完成明确记录「筛选已设置，点击查询」；连续 3 次准备任务列表/筛选失败时停止该实例并记录原因。
- **刷新页面卡死恢复**：任务结束刷新页面后先等 `domcontentloaded` 且确认无挂起整页导航，再重新筛选；刷新/筛选连续失败时按 2/3/4 秒退避，连续 3 次失败自动重启当前实例浏览器（最多 2 次），仍失败则停止该实例并记录「页面导航未完成」等原因，不再出现数百次重复下拉、空转数十分钟；首次失败保存 `failure_XX_refresh_failure.png` 现场图。
- **跳过表**：一列 xlsx/txt/csv，首行标题，其余任务名称；命中直接跳过。**未显式指定时默认用当前输出目录的 `跳过任务.txt`**（首行标题、逐条落盘，可直接作为下次 `--skip-tasks-file`）；它与原默认跳过表是同一张表，所以缺陷框/图片加载失败/未审核数超阈值三类任务，连同按钮未就绪、写入结果不明等转人工任务都追加到这里（本轮有照片下载/标注失败的任务除外，见「缺陷照片归档」）。输出目录没有该文件时首轮就是空表，不再读 state 目录里的旧 `跳过任务.xlsx`（跨输出目录共享，会把历史任务带进新一轮）；同一输出目录多次启停继续往同一张表追加，除非用户手工删除。显式配置的跳过表与输出目录表各写各的，未勾选默认时不会互相污染。**xlsx 跳过表只做增列不改整簿**：写入走 ZIP/XML 层，仅在目标工作表补 A 列单元格，保留原有样式、公式、合并单元格、数字格式与其他列；读表失败（含 xls/xlsm）一律放弃写入并记日志，**绝不按空表重写**把已有条目清空；多实例共用同一张表时串行化「读表-判重-追加」，同名不重复追加。
- **阈值与异常**：点进任务后，弹层任务名匹配当前任务且渲染出「未审核」文案（或出现本任务缩略图）即视为内容加载完成；随后还要等顶部弹层加载蒙层消失（该层会包住首图遮罩或盖住「审核完成」按钮）才开始点首图审核；每次点击缩略图切换图片也会触发该蒙层，脚本等其消失后再识别切换后的图片，避免把上一张误当成刚点击的图片；首图自身的图片加载遮罩不阻塞弹层就绪，单图仍按 `image_timeout` 等待并补审/跳过；弹层内容迟迟不渲染、顶部蒙层不消失、关闭失败或写入结果不明等一律刷新网页回任务列表继续，刷新失败每 60 秒重试，不中止整轮；新任务未审核数超过 `max_unreviewed`（默认 400）时关闭弹窗、跳过并记异常；未知异常也走同一刷新重试流程，不再中止整轮；停止口径见下条。
- **异常重试**：任务处理中抛出普通异常（如读取接口响应体失败、弹层超时）时，刷新网页后重新定位并重试同一条任务一次；重试成功则移除本次「审核中止」异常记录，仍失败才跳过并继续下一条。浏览器连接断开（Connection closed / Target closed 等）时跳过失败截图，保留并复用当前 Playwright 实例重建 CDP 连接后再刷新任务列表（同一线程对同步 API 重复 `start()` 会被 Playwright 判为 asyncio loop 内调用，不能重建实例）；Playwright 驱动进程本身退出（`Connection closed while reading from the driver`）时在同一线程停掉旧驱动并重建一次再连，单个重连周期最多重建一次，仍失败则继续按 10 秒间隔重试；任何刷新失败每 60 秒重试，不中止整轮。提交结果不明（WriteResultUnknown）不重试，避免重复提交。
- **实例重置**：客户端实例参数弹层提供「重置任务」，通过 `getActiveJob` 查该实例后端残留的 pending/running 任务，取消并等待 `getJob` 终态后清空该实例状态；只影响当前实例，不需要关闭重开客户端，也不影响其他并行实例。
- **进度与翻页**：进度条按任务总数统计，缺陷框、图片加载失败、未审核数超阈值等跳过的任务均计为完成；完成任务会从列表消失、后续页任务会前移（如第 3 页变第 2 页、第 4 页变第 3 页），因此下一轮从上一任务所在页继续扫描，需要换页时用分页跳转输入框直接跳到目标页，不逐页点「下一页」。
- **防休眠**：实例参数弹层勾选「运行时防止关屏/休眠」后，由客户端 Job 层统一请求宿主机关屏/休眠抑制（Windows `SetThreadExecutionState`；Linux `systemd-inhibit` + `xdg-screensaver`/`xset` 定时重置），并每 30 秒产生一次真实鼠标微动（Windows `mouse_event`；Linux `xdotool`/XTest），结束或停止后恢复；不勾选不触碰电源状态，不支持或失败只记日志，不影响审核。
- **停止**：协作取消每 200ms 检查一次；Playwright 点击/填表动作最多等 5 秒、页面跳转/刷新最多等 15 秒。点击停止且取消请求送达后，界面立即取消转圈，但该实例的「启动」保持禁用，直到核心 job.done/getJob 确认终态，避免旧任务仍在后端退出时重复启动而报「该实例已有任务在运行」；停止后不再关闭审核弹窗、不关闭受控浏览器。
- **输出**：每次运行独立输出目录，含 `审核汇总.xlsx`（「缺陷」「异常」两个工作表）、`审核汇总.jsonl`（每条缺陷/异常即时追加，进程中断也不丢已完成记录）、`run.log` 运行日志与 `跳过任务.txt`（缺陷框/加载失败/阈值跳过三类任务名，也是默认跳过表）。`审核汇总.xlsx` 每 20 个任务或累计 2000 行、以及运行结束时刷新，避免长跑时反复重写整张表；配置为 xlsx 的任务名称跳过表按 20 条批量刷新，txt/csv 即时追加。**同一输出目录多次启停会续写历史**：启动时先从 `审核汇总.jsonl` 逐行恢复，坏行/半截行跳过并告警、同时重写成干净文件；JSONL 无可用记录时用旧 `审核汇总.xlsx` 恢复并补写 JSONL。恢复的不只是行内容，还包括图片 GUID 与异常去重键，重跑不会重复登记；重试成功撤回的「审核中止」异常同步从 JSONL 删除，下次启动不会再被恢复。
- **缺陷照片归档**：不提供开关。未勾选「无视缺陷框」时，每登记一条系统缺陷框记录，就把对应照片**原图**保存到 `输出目录/线路名称/杆塔号/原文件名`（扩展名按系统原名保留，缺失时按图片类型补齐；线路/杆塔缺失或含非法字符时使用安全目录名），原图字节保持原样；同时用系统缺陷框坐标另存 `原文件名_标注.扩展名` 的标注图，标注结果返回 `drawn`（成功画出的框数）/ `skipped`（坐标非有限值、像素坐标落出画布、宽高小于 1px 而丢弃的框数），两者都计入运行汇总，`skipped>0` 时写日志便于核对框与图片尺寸是否匹配。下载优先复用审核弹层已加载的原图响应（按 `fileGuid` 匹配，直接归档页面实际取到的字节），其次用页面当前图片地址（缩略图地址改写 `isThumb=no`），最后才合成 `downLoadFile` 接口地址并复用页面请求中捕获的 Basic 鉴权头（不硬编码、不写日志），避免二次请求 401；**文件请求头只由「本站点文件下载接口的 GET 请求」整体刷新**——这类请求就是页面自己成功取到原图的请求，最可信；普通图片、缩略图、静态资源与文件接口的 POST 等请求只能**补缺**，绝不覆盖或移除已捕获的 `Allcore-Auth`/`Cookie`/`Blade-Auth` 等头。现场教训：页面只要加载过一张无鉴权头的静态图，旧实现就把整套文件头换成那几个头，后续原图下载全部 401（单轮 247 张里 246 张失败）。**缩略图（审核页 200×150 / 竖版 150×200）不得当原图归档**，只取真实原图地址；**可重跑、只补缺的一份 + 持久化归属索引**：输出目录下的隐藏文件 `.照片归属索引.json`（原子写）记录「相对路径 → `fileGuid` + 字节数 + sha256 + 标注文件名/大小」；写照片前先按目标目录 + 原文件名查已落盘的原图与 `原文件名_标注` 标注图——**只有索引证明是同一 `fileGuid`、且文件大小与 sha256 校验一致**才算已归档，两份齐全就直接跳过（不下载、不新增 ` (2)`）；只缺标注时读本地原图补标（不重新下载）；原图缺失才下载。索引缺失（旧版本留下的照片）时，只有当前刚取到的缓存字节与磁盘文件逐字节一致（sha256 相同）才复用并补写索引；证明不了就另存 ` (2)`，**绝不把旧原图配新缺陷框**。同名不同 `fileGuid`（同一次运行、跨任务或跨运行）一律另存 ` (2)`；只剩标注残留、原图被外部改写/删除时同样另存或按缺失补齐，历史文件与索引里的其他条目一律保留。目录查重只做一次 `iterdir` 建「文件名 → 路径」表，不在 1…999 个候选名上反复扫目录。同名文件自动追加 ` (2)`，绝不覆盖已有照片；单张下载/标注失败只记日志，不阻断审核，运行汇总记录保存张数与 `photo_download_failures`（原图下载失败）/`photo_mark_failures`（标注失败）/`photo_save_failures`（写入失败）分项计数，`photo_failures` 保留为总数为兼容旧口径。**本轮有照片下载/标注失败的任务不写输出目录跳过表、也不写任务名称跳过表**，否则下一轮再也不会进这个任务、漏下的照片永远补不上；下次运行补齐后按原规则正常写入。闸门口径为**同一任务跨刷新重试累计**：计数在 run 层进入任务前清零、`process_task` 内不清零（含重试），`process_task` 收尾与 run 层判定读写同一份累计值，日志不会一边说「不写」一边又写进表；不影响缺陷框/加载失败/超阈值等其他状态。照片永久失败（如接口 401）会每轮重进同一任务，日志会提示先核对鉴权/网络，修好后重跑同一输出目录即可补齐，确需跳过可手工把任务名加入跳过任务表；不另加审核守卫。下载兜底拒绝 206/`Content-Range` 部分内容与超过 80MB 的响应（声明长度与实收字节都判），当前页有多个原图地址时按顺序逐个尝试；页面已加载的 `blob:`/`data:` 图没有地址标识，只有记录的「本轮刚加载成功的那张图」fileGuid 与当前图片一致时才采用，否则拒绝而不是串图。下载失败、只加载到缩略图而拒绝保存、补存、标注失败/未画出框的日志即使带 HTTP 等接口细节，也必须进实时大屏摘要（只对技术日志做过滤，不得把这几类吞掉）。客户端执行摘要与「最近执行记录」在任一照片计数存在时展示照片段：有归档显示归档/标注张数，核心汇总提供 `photo_download_failures`/`photo_mark_failures` 时分别提示原图下载失败与标注失败，只有旧 `photo_failures` 时按整句「缺陷照片失败 N 张」提示。勾选「无视缺陷框」时不产生缺陷记录，也不归档照片、不写缺陷汇总。
- **无视缺陷框**：勾选后不读取/不判断 `picDefectFlg` 与 `taggingDetailInfo`，所有能加载图片都点审核完成；不产生缺陷记录、不归档照片，运行日志明确写「已勾选无视缺陷框：不判定缺陷框、不归档缺陷照片」。
- **缺陷框明细读取**：`taggingDetailInfo` 非 200、解析失败、等待超时一律抛 `TaggingDetailError` 交任务级异常/重试处理，不得返回空列表冒充「没有缺陷框」；只有接口明确返回空数组才算无框。后到的非 200 响应不覆盖更早的有效 200。`picDefectFlg` 已确认是系统缺陷框、但明细读不到时，照常归档照片并登记一行（缺陷描述留空）交人工核对。未知图片缺陷标识不再用空明细占缺陷行，只补存原图并记异常。
- **实例**：页面以实例卡片网格展示（约每行 4 个），顶部提供全部启动/全部停止和各实例运行状态；卡片内提供单个实例启动/停止、删除，点击卡片打开参数设置与实例日志弹层；每个实例独立启动网址、CDP 端口、profile 与参数，可同时运行；**每个实例（含默认实例）都有自己的浏览器目录** `state/browser-instances/defect_review-<实例标识摘要>/profile`——共用同一 `user-data-dir` 会让后启动的实例起不来或串号，实例标识里的非法字符被替换后会追加摘要避免撞名；显式配置的 `profile_dir` 优先。同一实例禁止重复启动任务，不同实例可并行。
- **升级后首次需重新登录**：实例 profile 目录随版本升级发生变化（旧的单实例共用目录不再复用），升级到本版后各实例第一次启动会在登录页停下，需要人工确认一次自动登录流程（账号密码已保存在 config.json，脚本会自动填写）；登录态落进新目录后，后续启动恢复正常。这是目录隔离的必然结果，不是掉登录 bug。
- **实时大屏**：启动实例后打开全屏屏保（`screensaver.html`），按实例自动网格展示简洁业务日志、总/单实例任务和当前图片进度；浏览器窗口保持最大化、不再自动排列或缩放，屏保覆盖其上。点击实例隐藏屏保、聚焦真实浏览器，右下角浮窗展示该实例完整日志和「返回实时大屏」按钮；关闭屏保二次确认，只关闭界面不停止审核。

## 六、配置与密钥管理规范

1. 三层配置：**内置默认值 < config.ini（只读）< config.json（GUI 可写）**。新应用的可调项在 `config.py DEFAULTS` 与 `config.example.json` 同步加默认值。
2. config.json 写入后 **chmod 600**（Windows 无权限位自动跳过）；真实值**绝不入仓**（.gitignore 已含 `toolkit/config.json`、`pylib/`）。写回是**原子操作**：同目录唯一临时名（`mkstemp`）→ fsync → `os.replace`，并发保存不互相踩、断电不留半截文件；旧文件 JSON 损坏时先备份成 `config.json.corrupt-<时间戳>` 再重建，旧文件存在但读不出来（权限/占用）时**拒绝覆盖**并报错，不让一次保存把用户配置清空。保存前按 `DEFAULTS` 递归校验类型（bool/int/str/dict/list 不互换、数字不收字符串、列表元素同类型），不符直接报错且不落盘；前端回传的 `has_password`/`password_source`/`secret_set` 等展示字段在写回前剔除，不落盘。
3. 路径解析（`config.config_path()`，优先级从高到低）：环境变量 `UVMP_TOOLKIT_CONFIG` > 冻结版用户配置目录（`~/.config/uvmp-toolkit/config.json` / Windows `%APPDATA%\uvmp-toolkit\config.json`；exe 旁 config.json 仅作旧版遗留自动迁移——安装包升级会清空安装目录，已踩坑）> 源码 `toolkit/config.json`。usb-agent service 经 unit 的 `Environment=` 指向同一份用户配置；deb 的 afterInstall 建初始配置（凭据由用户在设置页填写）。
4. SSO 凭据解析顺序：config.json `sso.*` → config.ini `[auth]`。新应用不自行读密码，统一 `config.sso_credentials(cfg)`。**密码类字段一律「留空/掩码 = 不修改」**：`save()` 递归摘掉空值或 `******` 的 `password`/`secret`/`token` 字段（含机巡实例 `params.password`），旧值保留；`masked_view` 把这些字段清空并只回 `has_password`/`secret_set`，`getConfig` 与 `saveConfig` 都不回传明文。
5. 状态目录（`state.py`）：linux `$XDG_DATA_HOME/uvmp-toolkit`，Windows `%LOCALAPPDATA%\uvmp-toolkit`。agent 与 GUI 同为桌面用户，共享同一状态目录；不再有 root/用户两份状态。
6. U盘挂载归属（Linux）：**运行期全部使用桌面用户**，包括 systemd agent service、核心、GUI 与 `udisksctl mount`；安装仍需 root/admin 一次（写 `/opt`、unit、计划任务）。服务通过 `User=@APP_USER@` 以桌面用户运行，`udisksctl` 挂载点落在 `/media/<用户>/GLKVM`（`user_id=<uid>`）；安装脚本同时写入 `/etc/polkit-1/rules.d/50-uvmp-toolkit.rules`（polkit ≥0.106 的 JS 规则）与 `/etc/polkit-1/localauthority/50-local.d/50-uvmp-toolkit.pkla`（polkit 0.105 / polkit-pkla-compat），允许该用户在锁屏/无活动会话时也挂载 U 盘；麒麟 V10 不同小版本的 polkit 机制不一，只写一种会被静默忽略。校验：`pkcheck --action-id org.freedesktop.udisks2.filesystem-mount --process $$`，或看 `udisksctl mount -b /dev/sdX` 是否还要求认证。重装无需重新识别或绑定，始终按卷标发现设备；每轮及挂载后均重新读取 `lsblk` 的真实挂载点，不依赖 `udisksctl` 输出语言。若检测到历史 root 挂载（`/media/root`、`user_id=0`），须在无同步任务时卸载并以桌面用户重新挂载…
7. 导出相关配置（键位与旧版兼容）：`order_export.query_workers=8`（钳 1..16）、`order_export.render_workers=4`（钳 1..16）、`order_export.lookback_days=62`、`order_export.batch_subdir=true`；显式 `render.chrome` 优先（设置页手选），留空则自动探测系统 Chrome/Chromium（官方直出需要真实浏览器；PDF 包版打印另可用自带 Electron）。并发只影响调度，不改产物格式/命名（见 §十）。
8. 集群（`cluster`）：`enabled`、`role`（hub|worker）、`cluster_id`、`secret`、`node_name`、`team_id`、`team_name`、`listen_host`（默认 `0.0.0.0`）、`listen_port`（默认 17890）、`advertise_host`、`hubs`（Worker 连的 Hub 地址列表）、`hub_peers`（多 Hub 对等，后续阶段使用）、`require_approval`、`heartbeat_sec`、`offline_sec`、`request_timeout_sec`、`export.chunk_size`（默认 6，钳 1..50）、`export.max_attempts`（默认 2，钳 1..5）、`export.request_timeout_sec`（默认 1800，钳 60..7200）。`secret` 至少 16 位、集群内所有节点一致；`getConfig`/`saveConfig` 不回传密钥，只回 `secret_set`，保存时留空或 `******` 表示不修改。节点间请求走 HMAC（时间戳 ±60s + nonce 120s 去重）。**管理接口（`/cluster/admin/*`）的本机来源校验是三件套**：Host 白名单（回环 + 本机网卡地址 + listen/advertise 地址）、Origin/`Sec-Fetch-Site` 同源（只认同端口，localhost 的其它端口也算跨站）、以及 `state/cluster/admin_token`（0600，首次访问生成，进程内缓存）随机令牌比对——只防「本机浏览器被跨站页面驱动」与 DNS rebinding，集群密钥不下发到管理接口；RPC 子进程读同一文件即可直连。
   - **统一审批**：Worker 只有两种终态——`approved`（入网成功，心跳带节点表）与 `pending`（等待 Hub 批准，Hub 侧 `registry.pending()` 可见）；`require_approval=false` 时入网即生效。GUI「集群」页的批准/拒绝、RPC `approveClusterNode`/`rejectClusterNode`、以及服务端读到的 `cluster_nodes.json` 都以同一份注册表为准，不另存第二份状态。
   - **结果/缓存归属**：集群指令结果与导出分片缓存都带 `requester` 归属——发起方本人可读，Hub 可取回它转发的任务（Hub 重启恢复路径），其他节点读不到（`ClusterForbiddenError`），避免缓存投毒与跨节点串读。升级前落盘、没有归属字段的旧分片缓存会被删除重算（否则会永久卡在 403）；旧结果文件仅在「合法 Hub 或该结果的目标节点」读取时放行并写审计日志。
   - **管理面安全**：登记/推送安装包只走本机管理接口（非本机一律拒绝）；更新包按 sha256 校验、文件名取 basename、目录固定；节点只落盘待手动安装，不自动提权。
   - 状态目录：`state/cluster/node.json`（持久 node_id）、`service.json`（服务状态/监听/错误，GUI 与 RPC 读取）、`registry.json`（Hub 注册表/审批）、`peers.json`（Worker 最近一次 Hub 心跳与节点表）。
   - 启停：`usb-agent` 每轮按 config 调用 `cluster.ensure()`；启用后最多约 15 秒生效；改监听地址/端口/角色会重启服务，改密钥/hubs/审批开关热更新。`usb-agent --once` 不启动集群服务。
   - 已实现：节点身份、入网申请/人工批准、心跳、节点表、Hub 指令转发与文件回传、多节点导出分片（§七之三）、节点更新分发（§七之四）。集群端口需在防火墙放行（默认 TCP 17890），Windows 登录计划任务决定无用户登录时节点离线。

## 七、U 盘监听与调度规范（服务端指令驱动）

- **唯一监听者**：`app.py usb-agent` 常驻。Linux 为桌面用户的 systemd service，Windows 为登录计划任务；GUI 启动时只补拉一次。`state/usb-agent.lock` flock 保证单实例：GUI 补拉/`--once` 抢不到立即退出；systemd 服务设 `UVMP_USB_AGENT_WAIT_LOCK=1`，抢不到时等待接管（GUI 拉起的实例退出后服务立即接岗），服务 unit 为 `Restart=always` + `StartLimitIntervalSec=0`，不会因反复失败永久停在 failed。
- **集群服务同进程**：`usb-agent` 每轮 `ensure()` 按 config 启停 `toolkit/cluster` 的 HTTP 服务（Hub 注册表/心跳、Worker 主动连 Hub）；`--once` 不启动。集群线程与 U 盘消费互不阻塞，服务失败只写 `state/cluster/service.json` 的 `last_error`，不影响 U 盘指令。
- **事件源**：Linux netlink uevent（block `add`/`remove`）+ 兜底轮询（默认 15s，`usb.agent.poll_sec`/`mounted_poll_sec` 可调）；事件去抖 4s。**挂载只由“设备出现且未挂载”触发**：宽限期内每秒复查桌面是否已自动挂载，宽限到点仍未挂载才 `udisksctl mount`（一次 3 轮、间隔 5s），失败按 30s→300s 退避重试（不再等下一次拔出/插入）。轮询只做发现/消费，绝不反复 mount，避免频繁挂载把系统拖卡。
- **挂载状态机**：先等桌面自动挂载 10s；仍未挂载才 `udisksctl mount`，**一次尝试 3 轮（间隔 5s）**，失败按 30s→60s→120s→300s 退避重试（不再“等下次插拔”）。**挂载成功、观察到挂载点消失（服务端取件断开共享、设备节点仍留在被控机）、设备拔出、收到 udev 插拔事件都会复位重试状态**：KVM 取件时盘会短暂断开而设备仍在（日志“U盘已卸载”而非“已移除”），沿用“每插入周期只挂一次”会永久挡住后续挂载（udisks 不保证自动挂载兜底、也不保证 udev 事件）。`usb-agent --once`/页面检查可强制立即重试；**客户端从不主动卸载**；`state/usb.lock` 串行化扫描/挂载/执行/结果写入，GUI 手动检查也不会并发。
- **挂载点校验**：每个挂载点先 `stat`/`os.access` 验可读可写。断线残留（EIO）与 root 挂载（EACCES）只记录原因并跳过，不再误判成“U 盘断开”；同名卷标有多个可用挂载点时，优先含指令文件、其次挂载目录最新的那个。`udisksctl` 拒绝会翻译成可操作提示（polkit 规则缺失 / 缺少 exfat 支持 / 设备刚被切走）。
- **指令协议**：盘根 `{app}_cmd.json`；agent 认领为隐藏 `.running`，执行后先原子写 `{app}_result_<id>.json`，再删指令。崩在中间由下次挂载补写 `interrupted`；结果写盘失败落 `state/usb-agent/pending/`，下次挂载补写。指令/结果都只允许盘根，禁止路径穿越。指令文件读失败（EACCES/EIO）按 IO 错误保留指令、下轮重试，不得按“指令损坏”写失败结果并删除。
- **心跳**：每轮检查写 `state/usb-agent/heartbeat.json`（无 U 盘也写，含 pid/ts/device/mount/readonly/state/last_error/last_command）；GUI 树障/交跨/派车页的「后台监听」行与 `getUsbAgentStatus` 读它，`state/usb-agent.lock` 被占用即 `running=true`。
- **服务端调度**：服务端全局 U 盘会话锁串行；结果驱动等待统一为**单次窗口：指令下发后等满 10 分钟取回一次**（`usbcmd.Once(usbcmd.DefaultResultWait)`；派车 `WORKLOG_DISPATCH_CMD_WAIT_MINUTES` 可调），不再 60s/3m 多轮 collect——每次 collect 都要断开共享，反复插拔会让被控机 udisks 卡死；轮次结束（成功/超时）`defer usbcmd.RestoreShare` 把 U 盘复挂回被控机，失败也不再把盘留在非共享；指令 TTL = 等待窗口 + 5 分钟。客户端不再有 09:15/23:55 定时、夜间兜底或 `--if-due`；对应设备文件传输仅在服务端 mount→等待结果的窗口内停用，结果取回即恢复。
- **日志留存**：任务日志 `state/logs/<job>.log` 30 天（GUI「清除日志」跳过 `usb-agent.log`，避免删掉常驻 agent 正在写的文件后整天无日志）；`usb-agent.log` 1MB×5 轮转、30 天，并同时写 journald（systemd 单元设 `UVMP_AGENT_JOURNAL=1`，日志文件丢失也能 `journalctl -u uvmp-toolkit` 排障）；`state/usb-agent/journal.jsonl` 指令审计 30 天/最近 1000 行；U 盘结果文件服务端取走即删，未取走客户端 7 天清理；服务端每条指令/结果落 `intranet_sync_cmd`，按 30 天每日清理。
- **U 盘锁只包临界区**：手动入口与常驻 agent 共用 `state/usb.lock`，但只包住真正碰 U 盘的两段（发现/复检挂载点、复制+落盘+sync）；登录、查询、分页抓取与 xlsx 生成全程不持锁——手动入口若全程持锁，agent 的指令要等整轮查询结束才能开始，服务端会先等到超时。指令模式下 agent 已持锁，后端不得重入；**每日派车单量少（预计 <10 单），不做每日分页处理**，按 `query_pcd_all_filter` 一次取全量即可。
- **手动调试**：`usb-agent --once` 或页面「检查 U 盘指令」只跑本地一次；页面手动入口发现服务端指令时返回 `skipped=agent_owned` 并保留指令（唯一消费者是 agent，避免服务端等不到结果文件）。不得恢复为系统定时器多路轮询，也不要再新增 `maybeRun*` 驻留 RPC。

## 七之二、集群指令转发与班组同步（Phase 2）

服务端 U 盘指令可带 `target.node_id` / `cluster` 与 `params.team_id/team_name/file`。`usb_protocol.normalize_command` 保留这些字段；`usb_agent` 按 `cluster_service.route_command` 分三类：

- `local`：无 target 或 target 为本机 → 现有 `backend.handle_command(job, cmd, mount)`。
- `remote`：本机是 Hub 且 target 为其他已审批节点 → `relay_command` 通过 `POST /cluster/command` 转发。转发前 `replace` 的新表从 U 盘读为 base64 附件；目标节点写入 `state/cluster/inbox/<id>/` 后在同一进程用 `handle_command(job, cmd, staging)` 执行，返回结果与产物；Hub 校验文件名/大小/`id/app` 后把产物写回 U 盘根并写结果。
- `deny`：集群未启用/本机不是 Hub/集群标识不一致/目标离线 → 直接写失败结果，不空等服务端窗口。

约束：

- 远端转发硬超时 `min(8 分钟, expires_at - 30s)`，服务端单次 10 分钟窗口留余量；超时/目标离线/班组不一致/目标未配置表均由 Hub 写 `ok=false` 结果。
- 目标节点校验 `target.node_id` 为本机、`cluster` 与 `cluster.cluster_id` 一致（任一侧为空时兼容旧单机）、`params.team_id` 与 `cluster.team_id` 一致（任一侧为 0 时跳过）。
- 结果增加 `target/node/relayed_by`；`data.file` 改写为产物 basename。Hub 重启时 `_recover_running` 会先按 `.running` 里的指令向目标 `/cluster/command/<id>` 取回结果，取不到才写 `interrupted`。
- Hub 挂载 U 盘时在盘根写 `cluster_nodes.json`（已入网节点 + 本机 Hub、`home_hub`、`sync_tables`）；服务端在树障/交跨会话中读取，刷新班组绑定页缓存。
- 节点 `sync_tables` 由 `tree_sync.local_path` / `crossing_sync.local_path` 计算 `{team_id,configured,exists}`；节点班组 ID 在「集群」页填写，必须与服务端绑定班组一致。
- 远端执行使用本机 `JobManager` 与应用表；任务历史/日志落在目标节点。产物大小上限 32 MiB，命令请求体上限 48 MiB；部署时注意 U 盘剩余空间。
- **跨班组 Hub 中转**：没有 GLKVM 的班组让 Worker 的 `hubs` 指向其他班组的 Hub；双方必须使用同一 `cluster_id`/`secret`，由该 Hub 管理员在「集群」页批准 Worker。Worker 保持自己的 `team_id`；Hub 只转发，目标 Worker 按指令 `params.team_id` 校验本班组。Hub 的 `cluster_nodes.json` 写入所有已审批节点（`home_hub`=该 Hub），服务端读取后按节点 `team_id` 归属班组；同步节点绑定只允许绑定本班组节点，`ResolveTeamSync` 再按节点的 `home_hub` 找到实际 Hub。结果沿 Hub 原路回写 U 盘。无 Hub 班组的 Worker 不要在自己机器上启用 Hub 角色。

## 七之三、集群导出分片（pcd_export）

派车单/轨迹导出可在集群内分片：发起节点（任意 Hub/Worker，GUI 所在机）把单号按 `cluster.export.chunk_size` 切成连续分片，多个节点并发执行。发起节点勾选时与其他节点并行；未勾选时不参与分片，只在本机其他节点全部结束后兜底剩余分片。

- **节点就绪**：`node_info.export_ready`（SSO 凭据或 token、浏览器/Electron、当前查询/渲染并发）随心跳上报；发起节点只接受 `online && export_ready.ready` 的选中节点，未就绪原因直接返回 GUI。发起节点未被勾选时仅作为兜底，不要求先就绪；被勾选时与其他节点一样校验。
- **分发**：`POST /cluster/export/run`（HMAC，`/cluster/export/*` 已列入公开端点白名单），body 为 `{job_id, chunk:{id,items,attempts}, options:{export_pcd,export_track,calibrate_noon,cluster_width}, concurrency:{query_workers,render_workers}}`。目标节点用本机 `JobManager` 在 **同一常驻进程**调用 `pcd_export.backend.run_cluster`（分片模式只写 `逐单/`，不合并、不出报告），把产物打 zip + base64 返回；`result.json` 按 `job_id/chunk_id` 幂等落盘，重复请求直接复用。单分片 zip 上限 32 MiB（base64 后仍在 48 MiB 响应上限内）。
- **并发**：GUI 每个节点单独设置查询/渲染并发（1..16）；分片内的查询/渲染仍走原有两级并行，节点总并发由用户显式控制。分片大小是全局配置，不随 GUI 变化。
- **重试**：分片失败按 `max_attempts` 重派；重派使用**新的 chunk id**（避免目标节点幂等复用旧失败结果），优先避开失败节点；单个单号失败则按全局 seq 生成单号重试分片。发起的兜底分片在远端全部结束后执行，保证任务闭环；最终仍失败的单号写入清单备注。
- **汇总**：发起节点按全局 `seq` 汇总 `rows/not_found/noon_rows`，复制各分片产物到最终批次 `逐单/`，复用 `pcd_export.backend.finalize_cluster` 合并 PDF、按全局顺序重算 12 点前页码、写 `_清单.csv`、`_未找到.txt`、`_12点前结束行程.xlsx` 与 `manifest.json`。文件名/命名规则与单机完全一致。
- **状态/取消**：发起节点状态在 `state/cluster/jobs/<job_id>/state.json`（含 chunks/rows/files），运行中可由 `clusterGetExport` 轮询；`clusterCancelExport` 取消本机 Job 并向在途节点 `POST /cluster/export/cancel`，目标节点取消对应分片 Job。集群服务重启后可读取落盘状态，但在途任务不会自动恢复，需重新发起。
- **安全**：节点间 HMAC + 集群标识校验；管理端 `start/status/cancel` 仍只接受本机来源（Host 白名单 + Origin/Sec-Fetch 同源 + 本机 0600 随机令牌）。分片结果按 `owner.json` 归属校验：只有发起方本人与转发的 Hub 能读，其他节点一律 403；无归属的旧缓存删除重算。节点只回传与请求分片匹配的文件名，发起节点只取 basename，防目录穿越。
- **验证**：`python3.15 -m unittest tests.test_cluster_export tests.test_cluster_service tests.test_cluster_protocol tests.test_cluster_registry -v` 覆盖分片、重试、汇总；真实多节点/大文件/取消仍需实机验证。

## 七之四、节点更新分发（Phase 4）

Hub 更新后可在「集群」页登记本机安装包并推送给已入网节点；节点只接收落盘并提示手动打开安装包，**不自动提权/静默安装**。

- **登记安装包**：`POST /cluster/admin/update/packages`（本机）传 `{path, platform, arch, version}`；服务计算 sha256/大小，写 `state/cluster/update_packages.json`。同一 sha 重复登记会更新元数据；平台/架构归一为 `linux|windows|darwin` 与 `amd64|arm64`。
- **移除登记**：`POST /cluster/admin/update/packages/remove` 传 `{id}`，仅删除登记元数据，不删除源安装包；RPC 为 `clusterRemoveUpdatePackage`。
- **自动匹配**：`POST /cluster/admin/update/push` 传 `{nodes:[node_id]}`；Hub 只处理已审批节点，按节点 `platform/arch` 选**最新登记**的匹配包；离线/无匹配包/地址无效逐节点记失败，不阻塞其他节点。仅发起 Hub 推送，不跨其他 Hub。
- **传输**：Hub 调目标节点 `POST /cluster/update/begin`（`update_id=sha256`、文件名、大小、sha、版本、平台/架构）→ 多次 `/cluster/update/chunk`（4 MiB/片 base64，48 MiB 请求上限）→ `/cluster/update/commit`。节点逐片落盘、校验总和 sha256，写 `state/cluster/updates/pending.json`；平台/架构与本机不一致直接拒绝。
- **手动安装**：节点「集群」页显示待安装卡片（版本/文件名/大小），点「打开安装包」由本机 GUI/RPC 进程调用 `platform_utils.open_path` 打开系统安装器；用户确认完成安装。无提示、不执行安装命令。待安装包在 `state/cluster/updates/<sha>/`，可重复打开。
- **跨班组**：Hub 的已审批节点可包含其他班组 Worker；更新包只按节点 `platform/arch` 匹配，不按班组隔离；节点收到后仅落盘待手动安装。
- **任务与状态**：Hub 推送使用 `JobManager` 的 `cluster_update` 任务，`clusterGetUpdate(job_id)` 轮询日志/进度；`clusterCancelUpdate` 取消当前推送（不删除已落盘包）。RPC：`clusterListUpdatePackages` / `clusterAddUpdatePackage` / `clusterRemoveUpdatePackage` / `clusterPushUpdate` / `clusterGetUpdate` / `clusterCancelUpdate` / `clusterGetPendingUpdate` / `clusterOpenPendingUpdate`。
- **安全**：节点间 HMAC + 集群标识；管理接口仅本机；文件名取 basename、更新目录固定；sha256 校验；无自动执行。更新包上限 2 GiB。
- **验证**：`python3.15 -m unittest tests.test_cluster_update tests.test_cluster_service tests.test_cluster_protocol tests.test_cluster_registry -v`；真实双节点跨平台/大包/安装器仍需实机验证。

## 八、平台兼容与离线依赖规范

1. 常规业务 Python 核心只准用标准库 + 既有纯 Python wheel；新依赖须 `py3-none-any` 且入 `offline_packages/`，**禁止需编译的原生模块**。唯一明确例外是课程自动学习（`course_autoplay`）：正式客户端收编 `playwright==1.62.0`、`greenlet`、`pyee`/`typing_extensions` 与对应平台 Node driver（按 Windows / 麒麟 amd64/arm64 分架构收编），构建参数 `--collect-all playwright --collect-all greenlet`；最终安装包离线安装后无需目标机 pip / `playwright install`，**禁止依赖目标机自行安装**。
2. 核心运行在**随包内置的 CPython 3.15.2 独立运行时**上（astral python-build-standalone，glibc 2.17+/aarch64 均有，PyInstaller 6 自带 aarch64 bootloader），版本与资产 SHA256 只有一处来源 `packaging/python-runtime.env`，三平台一致、不随设备 Python 漂移，**目标机无需安装 Python**。源码/测试侧要求 **Python 3.10+**（测试用括号化 `with`），实际开发与 CI 用 3.15.2；**不再承诺 Python 3.7 源码兜底**——`build_on_device.sh` 在 <3.10 解释器上只能产出旧版兼容核心且课程自动学习不可用。历史坑：`unlink(missing_ok=)` 是 3.8+ API，buster py3.7 核心包曾因此崩掉官方渲染器。
3. Windows 上不直接调 Win32 API（ctypes 的 libffi 依赖在 PyInstaller/conda 下脆弱——已踩坑）；用 `powershell -NoProfile -Command ...` 子进程替代。这类控制台子进程必须走 `platform_utils.run_hidden`（`CREATE_NO_WINDOW` + `SW_HIDE`）：GUI/隐藏启动的核心没有控制台，直接 `subprocess.run` 会每轮轮询闪一个 PowerShell 窗口（2026-11 实机反馈）。
4. 前端依赖锁定 `desktop/package-lock.json`（入仓）；本机装 electron 二进制用 `ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/`。
5. 路径一律 `pathlib`（Python）/ `path.join`（JS）；禁止硬编码 `/media/lenovo/...` 等机器相关路径。
6. shell 脚本必须 LF 行尾；bat 用 CRLF；`.gitattributes` 已锁（含 debian 无扩展名维护脚本——electron 时代在 desktop/build/*.sh）。
7. **壳层原生依赖的唯一例外（题库搜题）**：`quiz_search` 的 OCR 需要原生推理库，无法遵守第 1 条（Python 核心仍零原生依赖，该应用 backend.py 仅为注册占位）。实现全部在壳层 `desktop/electron/quizsearch/`：`onnxruntime-node`（钉版本；CPU EP 无 Intel/AMD/ARM 厂商绑定，替代原嗖嗖搜题的 MKL 方案）+ PP-OCRv4 mobile ONNX 模型（随仓入 `models/`，SHA256 见 models/README.md），推理跑在 `worker_threads` 线程（不拉起新进程：个别麒麟环境 utilityProcess spawn 即死——已踩坑，v2.5.4 起改用线程）。**题库 Excel 解析不再用 SheetJS**（已停维护且有安全问题）：`.xlsx` 走 `read-excel-file`、老式 `.xls`（BIFF8/CFB）走 `electron/quizsearch/xls-reader.mjs` 的内置读取器，模板生成走 `write-excel-file`，三者都在渲染层由 Vite 打包进 dist（主进程侧不引解析器，安装包才不会缺依赖）；格式按文件内容判定，不看扩展名。OCR 引擎状态以主进程 `engineReady/engineError` 为准（页面只解释「为什么没就绪」），线程创建失败/异常/退出都会内联显示。打包：`electron-builder.yml` 把 `node_modules/onnxruntime-node(-common)` 与 `electron/quizsearch/**` 列入 asarUnpack，`build/prune-ort.cjs`（afterPack）按目标架构剪枝 ort 预编译库；CI linux-amd64/arm64 job 有 buster 容器 glibc ≤2.28 门禁。`onnxruntime-node` postinstall 在 linux/x64 会联网拉 CUDA 库——CI 一律 `ONNXRUNTIME_NODE_INSTALL_CUDA=skip`。另注意 `desktop/package.json` 中 vite 打包进 dist 的渲染层依赖（vue/tdesign/**read-excel-file / write-excel-file**）一律放 devDependencies，放 dependencies 会被 electron-builder 重复收进 asar（曾致 asar 205MB）。
8. **Linux（麒麟/UKUI）悬浮窗与对话框的三条坑**（v2.5.2 踩坑记录）：
   - 悬浮框拖动/缩放：渲染层坐标全不可靠（screenX/movementX 在悬浮窗上合成输入恒为 0，真实环境亦丢值；pointer capture 在 X11 出窗断流；Windows `setSize` 缩小只生效一次——三连踩坑）——最终实现：渲染层只报「起/止」，位移由主进程 16ms 轮询 `screen.getCursorScreenPoint` 得出，缩放用 `setBounds`（非 setSize），收缩留 3px 余量让光标不越窗界，blur/pointercancel 兜底 dragEnd。回归用 `tools/drag_poll_test.cjs`（打桩光标）。另外推理线程在 asar 外运行，其依赖（onnxruntime-node 与 **onnxruntime-common**）必须全部 asarUnpack，漏一个即 Cannot find module（已踩坑，且 worker 的 exit 文案曾把真实错误覆盖成裸 code=1）。结果窗（result.html）复用同一套拖拽轮询：标题栏拖动移动、右下角柄缩放，位置与尺寸落盘 `settings.result`（x/y/w/h）下次开搜恢复；仅开一个扫描框时结果窗不分区（不显示框标），选项逐行排列。
   - UKUI 文件对话框扩展名过滤不可靠（xlsx 直接不显示）：`dialog:pickFile` 统一追加「所有文件」过滤器兜底。
   - 截屏裁剪**不用 `crop.getBitmap()`**：裁剪图的缓冲不是稠密 w×h×4（实测约 3 倍，行距继承原图），直接喂 OCR 读成斜纹垃圾、识别恒为空——整屏缩略图的 getBitmap 是稠密的，按行手工裁出稠密 BGRA（`_captureBox`）。回归：`tools/scan_e2e.cjs` 只断言回路响应不够（空文本也算响应），实采图片喂管线才算数。
   - 任务栏/应用中心图标两条根因：① X11 WM_CLASS 取 `Browser::GetName()`（Unicode 产品名匹配必失败，出齿轮占位）——`main.cjs` 在 linux 下 `app.setName('uvmp-toolkit')` 并 `setPath` 钉回 userData 原目录，desktop 文件 `StartupWMClass: uvmp-toolkit`；② 单文件 `linux.icon` 只装 1024 单尺寸——yml 不显式设 `linux.icon`，回退 `build/icons/` 目录全尺寸集合（`build/make-icons.cjs` 从 build/icon.png 生成）；`afterInstall.sh` 末尾刷 gtk 图标缓存。
9. **无边框窗口圆角（Windows/Linux 用 `setShape`）**（踩坑记录）：透明窗口会让 Windows 的 maximize/unmaximize 失效（v2.3.13 已踩坑），所以窗口保持不透明，仅把窗口区域裁成圆角。区域坐标是**窗口内容区的 DIP**，Chromium 内部按窗口所在显示器的缩放换算成物理像素（Windows `DesktopWindowTreeHostWin::SetShape` 乘 `GetScaleFactorForHWND` 后 `SetWindowRgn`，X11 走 `GetRootTransform`），因此**区域尺寸必须与当前内容区一一对应**。CSS 只负责画出曲线，曲线之外那几像素实测是窗口底色（`backgroundColor: #F5F7FA`），所以区域一旦与窗口不同尺寸就会直接暴露：区域比窗口大（还原动画期间仍按最大化尺寸生成）→ 该被裁掉的角没有被裁，四角呈窗口底色的方块，看起来就是「圆角丢失」；区域比窗口小（按旧尺寸生成）→ 右侧与底部被裁掉，关闭按钮那一列被切，看起来像「X 越出右边界」。几何与重算时机集中在 `desktop/electron/window-shape.cjs`：最大化/全屏恢复矩形——Windows 传空列表（Electron 文档与 `DesktopWindowTreeHostWin::SetShape` 的空列表快速路径都等于恢复矩形），Linux 显式传内容区整块矩形（`X11Window::SetShape` 没有空列表快速路径，空数组会走成空区域），都不依赖尺寸快照；普通态按 `getContentSize()` 生成逐行圆角并在尺寸落定后复核；尺寸未知不设区域。状态切换立即重算，拖拽缩放防抖，换屏/改缩放按 `displayShapeKey` 立即重算。CSS 侧 `.app-shell` 圆角与 `WINDOW_RADIUS` 同值，`.tb-btn` 显式 `box-sizing:border-box`/`padding:0`/`flex:0 0 auto`、`.tb-right` 不可压缩、`.tb-left` 溢出裁文字，避免长标题把最右一枚按钮挤出壳层。回归 `desktop/test/window-shape.test.cjs`（假窗口替身，不需要真机）；**真实 Windows 10 / 麒麟 / UOS 的最大化动画与高倍率缩放仍需实机确认**。区域几何按行内缩合并成带（1160×780 只 13 块，不是 780 块），Windows 高缩放时 Chromium 逐块乘缩放 `roundOut` 后由 Skia 二分求并，重叠不会丢块、每处过渡最多 1 物理像素取整差。

## 八之二、浏览器运行时与并行导出（Python）

### 浏览器通道（两条，分开验）

1. **官方页面直出（轨迹）**：`official_track.CdpBrowser` 以 `--headless=new --no-sandbox --disable-dev-shm-usage --remote-debugging-port=0 --user-data-dir=<临时 profile>` 拉起用户所选或自动探测的浏览器，端口走 profile 的 `DevToolsActivePort` 通告（360ent/Edge 不输出 `DevTools listening on`，不能依赖 stdout 解析），随后用 WebSocket 直连 CDP。导出的每个渲染槽位使用独立临时 profile 与工作目录 `state/browser-workers/<job>/worker-N`，成功收尾清理，失败保留诊断。退出走 CDP `Browser.close` + 进程树兜底，取消经 `job.add_cancel_hook(pool.stop)` 统一关闭。
2. **PDF 包版打印**：`vehicle_export.html_to_pdf` 优先调用自带 Electron（`--print-to-pdf`，路径由壳经 `UVMP_ELECTRON` 注入），缺失时回退用户所选/自动探测浏览器。自带 Electron 只承担本地 HTML → PDF，不承担需要真实登录态的官方页面渲染。
3. 证书边界：导出专用浏览器实例带 `--ignore-certificate-errors`（仅该独立 profile 的临时实例；官方地图/派车系统在目标网络可能需要），course 模式不做证书豁免；不要据此放开主窗口或其他业务的 TLS 校验。若实测为 SM2/TLCP 握手失败仍须公司国密浏览器。
4. CDP 自检：设置页「环境自检」→「CDP 渲染自检」由 `toolkit/selftest.py::run_cdp` 执行，只打开 `data:text/html;base64` 本地页（零网络），五步验证导航/eval/新 tab/截图 PNG/printToPDF，产物写日志目录 `cdp-selftest.png` / `cdp-selftest.pdf`；工作目录 `state/logs/cdp-selftest-work-<job>/`（含本次 profile 与浏览器日志）在**成功后或取消后整目录删除**，失败则保留现场供诊断。无浏览器或链路失败明确报错，不静默跳过。对应单元测试 `uvmp-toolkit/tests/test_selftest_cdp.py` 用 fake 浏览器，不联网。
5. **SSO 自检是真实只读探针**：`run_sso` 不只构造客户端——先换取凭证，再用同一客户端发一次「派车单查询第 1 页 1 条」（当日窗口、不加状态过滤）确认服务端接受当前凭据；任一步失败都以异常透传，不把「构造出客户端」当成凭据就绪。返回值含 `probe`（命中条数）与「只读查询：派车单第 1 页 1 条（服务端已接受当前凭证）」的检查说明。渲染自检（`run_render`）用本地 HTML 走包版打印，同样零网络。

### 并行导出（pcd_export，默认值已定）

- 查询池默认 `order_export.query_workers=8`（钳 1..16）：`bounded_map` + `ThreadPoolExecutor`，每个线程租借独立 `UvmpClient`/`requests.Session`（共享同一 `Auth`，token 刷新在锁内串行）；查询原语仍是 `vehicle_export.py` 的 runCode 直查/日期兜底，不改接口语义。
- 渲染池默认 `order_export.render_workers=4`（钳 1..16）：`RendererPool` 每个槽位独占一个 client、一个懒启动的 `OfficialTrackRenderer` 与独立工作目录；派车单渲染阶段完整结束后才进入轨迹渲染阶段，阶段内多单并行。
- 主线程按输入顺序收集结果并更新 `rows`、日志与进度；worker 不并发改共享 rows。`manifest.json` 的 `has/get/put` 同一把锁，`put` 先写同目录临时文件再 `os.replace` 原子替换（Windows `PermissionError` 有限重试），重跑自动跳过已导单据。
- 取消/异常：任务开始前 `job.check_cancel()`；取消后取消未启动 future、关闭全部渲染器并拒绝再启动浏览器（`RendererPoolClosed`）；单条渲染失败隔离并重建该槽位，不阻塞其余单据。
- 该并发是 **Python 原编排上的线程并发**，不是 Go 实现移植；不得把查询/渲染语义写成 Go 或外部导出进程协议。

## 九、CI 构建与打包约定（必读）

CI（公开仓根 `.github/workflows/release.yml`，2026-10 起客户端与后端同一条版本线 `release-vX.Y.Z` / `vX.Y.Z`，各 job 以 `defaults.run.working-directory: uvmp-toolkit` 进入本目录）：**release-init**（仅 tag：先建空 Release，避免构建 job 并发抢建 422）→ **client-windows / client-linux-amd64 / client-linux-arm64** 三 job 各自一 job 到底（核心装入 `resources/core/`；linux 核心在 buster 容器出、arm64 经 QEMU 模拟构建）→ **release-final** 补全 GitHub Release 说明并回推 tag 到 CNB。

- **版本来源**：`uvmp-toolkit/desktop/package.json` 的 `version` 是唯一版本源；tag 构建以 `npm version --no-git-tag-version --prefix desktop` 注入版本号，不另设 `version.json`。
- **内置运行时**：三平台 job 都从 `packaging/python-runtime.env` 读 CPython **3.15.2** 的资产名与 SHA256，下载后校验，失败即中止（不回退 latest）；Python 依赖全钉版本取自 `packaging/requirements-core.txt`，装完必跑 `pip check`。
- **三平台门禁分布**（不得笼统写成三平台都跑同一套）：
  - `client-windows`：Python unittest + selfcheck → PyInstaller 核心 → CDP 冒烟（缺宿主浏览器时明确报告跳过）→ desktop node 测试 → electron-builder NSIS 打包 → GUI 冒烟（`UVMP_CI_SMOKE` 真实渲染）；
  - `client-linux-amd64`：buster 容器内构建核心（含 selfcheck/RPC ping）→ CDP 冒烟（缺宿主浏览器时明确报告跳过）→ desktop node 测试 → deb/tar.gz 打包 → OCR 运行时 glibc 门禁（≤2.28）→ xvfb GUI 冒烟；

- CNB 构建链说明：CNB 无 Windows 构建节点，Windows 客户端只在 GitHub Actions 构建；wine 跨构建已试验放弃。
- 下载入口在壹匣**登录页推广区**（j1toolkit `login.html`，`client.html` 独立取件页已下线、sys_app 种子启动时自动清理）：直链 CNB 公开仓 Releases 最新 tag，安装包不托管本站。

7. 打包资产文件名一律 ASCII（GitHub 资产名剥非 ASCII——已踩坑）。
8. **electron-builder 一律在 `desktop/` 内运行**（CI 与 build_local.ps1 均已改为 `cd desktop` 后执行）：`afterPack` 等钩子路径按**工作目录**而非 projectDir 解析，从仓根 `--projectDir desktop` 调用会找不到 `build/prune-ort.cjs`（已踩坑）。
9. **渲染唯一路径：官方页面直出**（official_track.py 出 PNG → html_to_pdf 包版）。内置模板已删除且禁止加回；渲染器不可用必须报错引导用户在设置页选公司浏览器；dev.mock 联调用 `_write_stub_pdf` 占位（勿用于生产）。

## 九之二、本机构建通道（GitHub Actions 额度耗尽时）

CI（公开仓 GitHub Actions）每次发版全链——服务端双架构构建 + 客户端三 job——约耗 100+ 分钟额度（Windows 双倍计），公开仓免费额度 2000 分钟/月。
额度耗尽时在本机出包：安装包与 CI 使用同一份 electron-builder.yml，本机还会额外留下不发布的绿色 zip/tar.gz。

| 目标                                          | 本机（Windows）可做？ | 说明                                                                                                                                                                                                                                                         |
| --------------------------------------------- | --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Windows 核心 + Setup exe + 绿色 zip（仅本机） | ✅                    | `powershell -File packaging/build_local.ps1`                                                                                                                                                                                                                 |
| 麒麟 deb/tar.gz（amd64/arm64；tar.gz 仅本机） | ⚠️ 半可               | electron-builder 跨平台组 deb 没问题，但 **linux 核心必须在 linux 上构建**（PyInstaller 不跨平台）；本机无 Docker/WSL 时：在麒麟机上跑 `packaging/build_on_device.sh` 产出核心目录，拷回后 `build_local.ps1 -LinuxCoreAmd64 <目录> [-LinuxCoreArm64 <目录>]` |

要点：

- **绿色 zip/tar.gz 只属本机通道**：供本机/离线分发使用，不上传 GitHub Release、不进入 CNB 取件；CI 正式发版仍只发布 3 件安装包。
- 本机构建走 npmmirror 镜像拉 electron/winCodeSign/nsis（脚本内置 `ELECTRON_MIRROR`；github.com 直连不通也能构建）。
- npmmirror 重定向 URL 带签名 → electron-builder 缓存目录名每次随机 → winCodeSign 里的 darwin 符号链接在非管理员 Windows 解不开 → 反复重试失败（已踩坑）。`build_local.ps1` 自动处理：预下载三个 7z 到 `packaging/.eb-binaries/`（不入库）+ 起 127.0.0.1:8899 静态服务让 URL 稳定，并给 `app-builder.exe` 打等长二进制补丁 `-snld`→`-snl-`（7-Zip 21.07 不认 -snld；-snl- 把符号链接落成普通文件，无需特权）。
- `build_on_device.sh` 离线构建：**依赖分界是 Python 3.10**（`requirements-core.txt` 里 requests 2.34 / pypdf 7 / PyInstaller 6 都要求 3.10+）。<3.10 的解释器只构建旧版兼容核心（钉死 `pyinstaller==5.13.2`、`requests==2.31.0`、`gmssl==3.2.2`、`pypdf==3.17.4` 等 3.7 可用版本），**课程自动学习不可用**；完整构建请用 Python 3.12+（脚本提示口径；正式 CI 与 `build_linux_container.sh` 内置 CPython 3.15.2），unittest 门禁在 <3.10 时明确报告跳过而不是假装跑过。wheel 包需在能上网的机器上 `pip download -r packaging/requirements-core.txt -d wheels/ --only-binary :all:` 预置。
- 若某版本只改了 Python 业务代码，linux 核心可直接复用上一版 release 包里的 `resources/core/` 目录（仅限核心代码零变更时）。

- 「自动校准行程结束时间」（前端勾选项 / 参数 `calibrate_noon` / CLI `--calibrate-noon`）：
  行程段结束时间早于当日 12:00 的轨迹（车载定位系统异常口径），按 1 小时逐次叠加校准至

  查询窗口不改（不伪造 GPS 数据）；`_12点前结束行程.xlsx` 附校准后两列便于对照。
