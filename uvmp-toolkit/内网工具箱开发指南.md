# 内网工具箱开发指南

> 本文档是内网工具箱的架构说明与开发规范，面向后续接入更多内网应用的开发者与 AI 编码助手。
> 改动前请先读完第一、二章；新增应用按第五章示例执行；所有规则延续壹匣（j1toolkit）约定：简体中文注释、最小改动、密钥不入仓、交付完整代码无占位。

## 一、项目定位与架构

### 1.1 定位

内网工具箱是运行在**内网被控机**（银河麒麟 V10 SP1 amd64/arm64 优先，兼顾 Windows 10+）上的**原生桌面客户端**（Electron + Vue，QQ NT/网易云音乐同路线），一个长期演进的本体外壳，各业务以**应用（插件）**形式接入。界面为现行 **11 页 Vue**：工作台、执行历史、设置 3 页壳层 + 题库搜题、轨迹导出、树障同步、交跨同步、派车同步、学堂刷课、脚本测试 7 个业务页 + 集群 1 个平台页。

> 现行唯一正式轨为 Electron + Python；历史 Go 重构轨与相关构建脚本已整体删除，仓内不保留任何构建引用。

首批应用：

| 应用 id           | 名称     | 职责                                                                                                                                                    |
| ----------------- | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `quiz_search`     | 题库搜题 | 屏幕双扫描框实时 OCR 搜题（壳层应用：截屏/OCR/悬浮窗全在 Electron，见 §8.7）                                                                            |
| `course_autoplay` | 学堂刷课 | 接管受控浏览器自动学习学堂平台课程：全分页扫描、断点续刷、暂停/切换培训班恢复（引擎复用仓根 `course_autoplay_trial.py`，见 §4.6）                       |
| `pcd_export`      | 轨迹导出 | 按派车单号清单（xlsx/文本）按序导出派车单/轨迹 PDF；旧 Python 编排 + 本地线程并发（见 §八之二）                                                         |
| `tree_sync`       | 树障同步 | 按服务端经 U 盘下发的指令（tree_sync_cmd.json）同步树障统计表 xlsx：snapshot 上盘 / replace 回内网，执行后写结果文件                                    |
| `crossing_sync`   | 交跨同步 | 按服务端经 U 盘下发的指令（crossing_sync_cmd.json）同步交跨统计表 xlsx：snapshot 上盘 / replace 回内网（契约同 tree_sync，独立指令文件/结果/config 段） |
| `daily_sync`      | 派车同步 | 按服务端指令导出当日派车单 xlsx 写入 U 盘（GLKVM），执行后写结果文件                                                                                    |

### 1.2 技术选型（已定，勿擅自更换）

**Electron 33（壳） + Vue 3 + TDesign（界面） + Python 核心 sidecar（业务）。**

- 桌面壳用 Electron：UI 上限高、跨平台稳、与壹匣同为 Web 技术族（TDesign 组件同源）；壳层负责窗口/托盘/单实例/原生文件对话框、题库搜题的截屏与 OCR、以及自带 Chromium 的离线 PDF 打印
- **业务逻辑全部留在 Python**（`toolkit/`）：SSO 国密登录、请求签名、导出编排、xlsx 契约、U盘挂载、定时链路——这些是已在内网验证的逆向成果，**绝不重写到 JS**
- 壳与核心经 **stdio JSON-RPC** 通信（`toolkit/app.py rpc`）：免端口/令牌，父子进程 1:1 生命周期，PyInstaller 好打包
- **pcd_export 为旧 Python 原语上的原生线程并发，不是 Go 移植**：查询/渲染原语仍是 `vehicle_export.py`、`uvmp.py`、`official_track.py`；`toolkit/apps/pcd_export/parallel.py` 用 `ThreadPoolExecutor` 做有界并行。查询默认 8 路（钳 1..16），渲染默认 4 路（钳 1..16）；查询阶段结束后，派车单渲染、轨迹渲染两个阶段先后执行，每阶段内多单并行；每个渲染槽位独占 client、Session、renderer 与浏览器 profile；主线程按输入顺序收集结果并更新清单/进度；`manifest.json` 并发互斥 + 临时文件原子替换写入；取消时统一关闭渲染器、取消未启动任务，成功收尾清理临时目录（失败保留诊断）
- 题库搜题的截屏/OCR/悬浮窗在 Electron 壳层（`onnxruntime-node` + PP-OCRv4 mobile，推理跑 `worker_threads`）；课程自动学习复用 Playwright 引擎；CDP 渲染自检为纯 Python（`official_track.CdpBrowser` 打开 `data:` 本地页，零网络），不依赖外部导出工作进程
- 官方页面直出：`official_track.CdpBrowser` 用 `--headless=new` + 独立临时 profile + CDP 驱动用户所选/自动探测的浏览器；PDF 包版打印优先用自带 Electron（`UVMP_ELECTRON` 由壳注入），没有时回退用户所选/自动探测浏览器。两条通道分开验证，不互相冒充
- 历史教训：PyQt5 方案（v1.x）因 PyInstaller/Qt DLL 收集与 NSIS 手写脚本编码问题翻车，已废弃

### 1.3 架构图

```
内网工具箱.exe（Electron 33）
  ├─ 主进程 electron/main.cjs：窗口/托盘/单实例/原生对话框/--print-to-pdf
  │     ├─ core.cjs：spawn resources/core/uvmp-core(.exe) —— stdio JSON-RPC
  │     └─ window-state.cjs：最小化恢复/显示/聚焦
  ├─ preload.cjs：contextBridge 暴露 window.core（call/onEvent/pickFile/pickDirectory/showItem）
  └─ 渲染进程：Vue3 + TDesign 11 页（desktop/src/pages/*）

uvmp-core（Python，PyInstaller console onedir）
  ├─ app.py usb-agent  → U 盘单监听（udev 事件 + 兜底轮询；systemd/计划任务常驻）
  ├─ cluster/          → 节点集群服务（同进程托管：入网审批/心跳/节点表；指令转发后续接入）
  ├─ app.py rpc        → RPC 服务（getConfig/runJob/…，事件主动推送）
  ├─ app.py selfcheck / daily-export / order-export / tree-sync / crossing-sync / run-script
  ├─ usb_protocol.py / usb_agent.py ← 指令/结果契约、挂载状态机、命令认领与结果落盘
  ├─ apps/<id>/backend.py           ← 业务编排（GUI/CLI/RPC/agent 共用同一函数）
  ├─ apps/pcd_export/parallel.py    ← 有界线程并发 / 渲染槽位池
  ├─ selftest.py                    ← 渲染、SSO、CDP 三项环境自检
  ├─ vehicle_export.py / official_track.py（接口/渲染原语）
  └─ course_autoplay_trial.py / browser_automation.py（课程引擎/受控浏览器辅助）
```

**分层铁律**：`toolkit/` 与 `apps/*/backend.py` 禁止 import 任何 GUI 依赖（无头环境要跑）；Electron/Vue 只做展示与交互。

# 核心 CLI（无头场景；冻结版二进制用法相同）

# 环境自检（设置页「环境自检」卡片）：render / sso / cdp 三种，走任务事件模型

## 四、插件规范

### 4.1 应用 = 三处落点

1. `toolkit/apps/<id>/app.json`：声明（id/name/badge/desc/order）
2. `toolkit/apps/<id>/backend.py`：业务后端（契约见 4.2，GUI 无关）
3. `desktop/src/pages/<XxxPage.vue>`：界面（并在 `App.vue` 的 `PAGE_MAP` 登记一行）

### 4.2 backend.py（契约）

```python
APP_ID = "my_app"

def run(job, params: dict) -> dict:      # 必需：任务入口；返回业务摘要 dict
def handle_command(job, cmd: dict, mount: str) -> dict:
                                         # 可选：usb-agent 指令入口（cmd 已归一；
                                         # 失败直接抛异常，agent 统一写结果/删指令）
def status(cfg: dict) -> dict:           # 可选：状态卡数据源（RPC getAppStatus）
def preview(params: dict) -> dict:       # 可选：输入预览（RPC preview）
def launch_browser(cfg: dict) -> dict:   # 可选：启动/复用受控浏览器（RPC launchAppBrowser，见 §4.6）
```

`run` 内规范：`job.log()` 逐行汇报；`job.set_progress(cur, total, label)`；工作单元间 `job.check_cancel()`；单条失败不阻塞整体；产出落用户目录，中间件成功后删除。

### 4.3 Vue 页面规范

- 组件用 **tdesign-vue-next**；主题一律走 `src/theme.css` 的 token（政企蓝白：品牌蓝 #0E3DA8 / 页面底 #F5F7FA / 正文 #1D2129 / 边框 #E5E6EB…，与 j1toolkit 双端同套），禁止自定义新色系；特征元素（白卡 12px 圆角轻影、浅蓝底导航图标块、直角警示块）样式已在 theme.css 里。
- 调核心一律走 `src/api.js`：`call(method, params)`；任务用 `runJob(appId, params, {onLog,onProgress,onDone,onError})`（返回 `{jobId, cancel, finished}`；`finished` 可等待旧任务到达终态）。
- 文件/目录选择用原生对话框：`pickFile(filters)` / `pickDirectory(defaultPath)`（别让用户手填路径）；打开产物目录：`call('openPath', {path})`；文件管理器定位：`showItem(path)`。
- 任务结果统一用 `components/TaskResult.vue` + `lib/task-result.mjs`：状态/摘要/产物/折叠排错日志；失败与启动失败自动展开日志并滚入视野。历史记录统一用 `components/HistoryCard.vue` 与 `lib/history.mjs`，参数回填用 `lib/restore-params.mjs`（只回填表单，不自动执行）。
- 11 页由 `App.vue` 的 `PAGE_MAP` 注册并经 `keep-alive` 保留；侧栏、命令面板（`Ctrl+K`）、`Ctrl+,` 进设置均属壳层，页面不自行实现系统全局热键。

### 4.4 RPC 方法表（`toolkit/rpc.py` 维护）

`ping` / `getSystemInfo` / `getConfig` / `saveConfig(updates)` / `getApps`（每项含 `has_browser` 标记） /
`getAppStatus(app_id)` / `launchAppBrowser(app_id)` → 启动/复用受控浏览器（仅实现 `launch_browser` 的应用可用；同步调用，不创建 Job） /
`preview(app_id, params)` / `runJob(app_id, params)` → `{job_id}` /
`cancelJob(job_id)` / `getJob(job_id)` / `getHistory(app_id)` / `openPath(path)` /
`getJobLog(job_id)` → `{text}`（任务完整日志全文） / `deleteHistory(app_id[, job_id])` → `{records, files, skipped}`（删执行记录：传 job_id 删单条，不传清空该应用，连带任务日志/档案） / `clearLogs()` → `{removed, skipped}` / `getLogStats()` → `{dir, files, bytes}` /
`getDevScriptEnv()` → `{python, version, frozen, config_path, state_dir, encoding}`（脚本测试页显示实际运行环境） / `getUsbAgentStatus()` → `{running, heartbeat, heartbeat_path, log_path}`（`running` 以单实例锁是否被占用判定，`heartbeat` 为 agent 每轮检查落盘的心跳；无 U 盘时也有，用于区分“服务没在跑”与“在跑但 U 盘未挂载/不可读”） /
`getClusterStatus()` → 集群节点状态（本机身份、服务状态、待审批/已入网节点、Worker 心跳） / `getClusterNodes()` → `{nodes, pending}` / `approveClusterNode(node_id)` / `rejectClusterNode(node_id)` → 本机 Hub 审批节点并返回最新状态 /
`clusterStartExport(params)` → `{job_id, total, nodes}`（发起节点切分派车单/轨迹导出；`params.nodes` 为选中节点及各自 `query_workers`/`render_workers`） / `clusterGetExport(job_id)` → `{job, logs, queue}` / `clusterCancelExport(job_id)` → 取消本机发起的集群导出并向在途节点发取消
`clusterListUpdatePackages()` / `clusterAddUpdatePackage({path, platform, arch, version})` / `clusterPushUpdate({nodes})` → `{job_id, total, nodes}` / `clusterGetUpdate(job_id)` → `{job, logs}` / `clusterCancelUpdate(job_id)` / `clusterGetPendingUpdate()` → `{pending}` / `clusterOpenPendingUpdate()` → 打开待安装包（手动安装，不自动提权）

集群服务跑在 `usb-agent` 常驻进程内；RPC 子进程经本机 `127.0.0.1:<listen_port>/cluster/admin/*` 读取/审批（只允许本机来源），读不到时回退到 `state/cluster/service.json`、`registry.json`、`peers.json`。节点间请求走 HMAC（见 §六 第 8 条）。

U 盘监听不再由 GUI/OS 定时器逐分钟驱动：`app.py usb-agent` 常驻（systemd 服务 / Windows 登录计划任务），GUI 启动时只补拉一次（flock 单实例）。指令消费、挂载、结果落盘均在 agent 进程内完成，任务历史仍写 `state/history/<app_id>.jsonl`。

事件（核心→壳主动推）：`job.log{job_id,line}`、`job.progress{job_id,current,total,label}`、`job.done{job_id,job}`、`core.exit{code}`。
新增方法 = `rpc.py` 里加一个 `m_<名字>` 方法（自动入表），同步更新本节。

> 环境自检走 `runJob` 的特殊 app_id：`selftest:render` / `selftest:sso` / `selftest:cdp`，由 `toolkit/selftest.py` 实现，复用同一套 Job 事件与历史，不注册为 `toolkit/apps` 应用。
> `quiz_search` 例外：实时截屏/OCR/悬浮窗不适合 stdio RPC，**不新增核心 RPC**；壳层 IPC 以 `quizSearch:*` 命名（`electron/quizsearch/index.cjs registerIpc`），渲染层经 `window.core.quizSearch.*` 调用。

### 4.5 任务（Job）模型

- 核心内 `jobs.JobManager` 统一管：日志写 `state/logs/<job_id>.log`，结束写 `state/jobs/<id>.json` + `state/history/<app_id>.jsonl`（页面历史数据源）。
- 内存有界回收：终态 Job 在内存中只保留最近 `MAX_TERMINAL_JOBS = 50` 个（`jobs.py`，超出按 job_id 降序回收内存对象）——防常驻进程内存无限涨；**只收内存对象，任务档案（state/jobs/）与日志文件（state/logs/）不受影响**，`getJobLog` / `getHistory` 仍可查全部历史。
- 日志清理：`app.py` 各入口（rpc/daily-export/order-export 等）启动时 `state.prune_old_logs(30)` 自动删除 30 天前的任务日志/档案；设置页「日志管理」卡显示占用（`getLogStats`）并可一键清除全部（`clearLogs`，运行中任务的 .log 被占用时跳过计数）；历史记录页「日志」按钮经 `getJobLog` 查看单次任务完整日志。
- 执行记录删除：各应用页「最近执行记录」卡统一用 `components/HistoryCard.vue`（新应用接入直接复用即获得删除能力）——单条「删除」与「清空」均走 `deleteHistory`（`state.delete_history_records`）：删 `history/<app_id>.jsonl` 对应行并连带删 `logs/<job_id>.log`、`jobs/<job_id>.json`，app_id/job_id 正则校验防路径穿越，占用文件跳过计数；root 镜像侧的历史不受影响（镜像只追加，不同步删除）。
- 取消钩子：长任务的浏览器/线程池等资源经 `job.add_cancel_hook(fn)` 统一释放，取消后任务进入 `cancelled`，不得留下孤儿浏览器或线程池。
- 状态机：pending → running → success / failed / cancelled；`job.on_done` 在终态落定后触发（RPC 事件时序正确性靠它，勿在业务 finally 里自行推 done）。

### 4.6 课程自动学习（course_autoplay）应用要点

- **引擎复用，不另起 CDP 实现**：仓根 `course_autoplay_trial.py` 即课程引擎（PyInstaller 以 `--add-data course_autoplay_trial.py` 收编进 `_MEIPASS` 根，backend.py 运行时 importlib 按路径加载）；通用浏览器启动/状态辅助为 `toolkit/browser_automation.py`（Playwright 连本机 CDP，浏览器可执行文件复用 `render.chrome`）。
- **可选后端契约 `launch_browser(cfg)`**：实现它的应用才可被 RPC `launchAppBrowser({app_id})` 调用（`getApps` 以 `has_browser` 标记）。打开浏览器不是 Job、不产生任务档案；已有受控浏览器时直接复用，不重复启动。
- **用户流程**：填启动网址（随 config.json 永久保存）并点「打开浏览器」，自动访问该网址 → 人工登录并打开任意同学堂平台页面契约的「课程设置」列表且置前台 → 勾选「仅扫描（不进入课程）」或点「开始学习」（主按钮只有开始学习，扫描是 checkbox）→ 运行中可点「暂停学习」；完成提醒以点击「开始学习」时的模式为准：启动时为正式学习且本轮无未完成课程（`pending=0`）才弹窗，扫描模式或仍有未完成课程不弹。
- **暂停/检查点语义**：点击暂停立即中断当前等待并释放开始按钮；若旧任务尚未到达终态，再次开始会等待旧任务退出，不与旧任务重叠运行。暂停只断开 Playwright、关闭当前学习弹窗，不杀受控浏览器、不清登录态；暂停回滚当次尝试、不记失败。检查点按 trainid/列表分别持久化到 `state/course-autoplay/checkpoints.json`（续刷页、真实失败次数、已处理数、跳过项及原因）；切到新培训班用独立检查点，切回可恢复。正常完成一轮后 `active=false`，下次开始为新一轮（旧跳过项可重试）。任务历史 `cancelled` 且 `result.paused=true` 显示「已暂停」。日志走 `job.log` / `job.set_progress` / 任务档案，失败截图 `state/logs/<job_id>_failure_*.png`。
- **引擎既有能力保持**：多标签识别、全分页扫描、视频真实 `ended` 等待（拖动后每轮限 30 秒，超时重新定位播放器并重拖，连续 3 轮失败交回单课重试）与学习记录上报确认、非视频课件加载、单课 3 次（`course_autoplay.max_attempts`）后跳过继续、末页后从第 1 页从头复核、刷新后直接跳回续刷页。
- **配置**（`config.py DEFAULTS` 与 `config.example.json` 同步）：`browser_automation{cdp_url 默认 http://127.0.0.1:9222（仅本机回环）、profile_dir 空=state/browser-automation/profile、start_url 空=空白页（填写后永久保存并自动访问）、step_timeout=120}`、`course_autoplay{max_attempts=3}`。

## 六、配置与密钥管理规范

1. 三层配置：**内置默认值 < config.ini（只读）< config.json（GUI 可写）**。新应用的可调项在 `config.py DEFAULTS` 与 `config.example.json` 同步加默认值。
2. config.json 写入后 **chmod 600**（Windows 无权限位自动跳过）；真实值**绝不入仓**（.gitignore 已含 `toolkit/config.json`、`pylib/`）。
3. 路径解析（`config.config_path()`，优先级从高到低）：环境变量 `UVMP_TOOLKIT_CONFIG` > 冻结版用户配置目录（`~/.config/uvmp-toolkit/config.json` / Windows `%APPDATA%\uvmp-toolkit\config.json`；exe 旁 config.json 仅作旧版遗留自动迁移——安装包升级会清空安装目录，已踩坑）> 源码 `toolkit/config.json`。usb-agent service 经 unit 的 `Environment=` 指向同一份用户配置；deb 的 afterInstall 建初始配置（凭据由用户在设置页填写）。
4. SSO 凭据解析顺序：config.json `sso.*` → config.ini `[auth]`。新应用不自行读密码，统一 `config.sso_credentials(cfg)`；密码在 UI 留空 = 不修改（rpc.py 剥除空 password 键）。
5. 状态目录（`state.py`）：linux `$XDG_DATA_HOME/uvmp-toolkit`，Windows `%LOCALAPPDATA%\uvmp-toolkit`。agent 与 GUI 同为桌面用户，共享同一状态目录；不再有 root/用户两份状态。
6. U盘挂载归属（Linux）：**运行期全部使用桌面用户**，包括 systemd agent service、核心、GUI 与 `udisksctl mount`；安装仍需 root/admin 一次（写 `/opt`、unit、计划任务）。服务通过 `User=@APP_USER@` 以桌面用户运行，`udisksctl` 挂载点落在 `/media/<用户>/GLKVM`（`user_id=<uid>`）；安装脚本同时写入 `/etc/polkit-1/rules.d/50-uvmp-toolkit.rules`（polkit ≥0.106 的 JS 规则）与 `/etc/polkit-1/localauthority/50-local.d/50-uvmp-toolkit.pkla`（polkit 0.105 / polkit-pkla-compat），允许该用户在锁屏/无活动会话时也挂载 U 盘；麒麟 V10 不同小版本的 polkit 机制不一，只写一种会被静默忽略。校验：`pkcheck --action-id org.freedesktop.udisks2.filesystem-mount --process $$`，或看 `udisksctl mount -b /dev/sdX` 是否还要求认证。重装无需重新识别或绑定，始终按卷标发现设备；每轮及挂载后均重新读取 `lsblk` 的真实挂载点，不依赖 `udisksctl` 输出语言。若检测到历史 root 挂载（`/media/root`、`user_id=0`），须在无同步任务时卸载并以桌面用户重新挂载…
7. 导出相关配置（键位与旧版兼容）：`order_export.query_workers=8`（钳 1..16）、`order_export.render_workers=4`（钳 1..16）、`order_export.lookback_days=62`、`order_export.batch_subdir=true`；显式 `render.chrome` 优先（设置页手选），留空则自动探测系统 Chrome/Chromium（官方直出需要真实浏览器；PDF 包版打印另可用自带 Electron）。并发只影响调度，不改产物格式/命名（见 §十）。
8. 集群（`cluster`）：`enabled`、`role`（hub|worker）、`cluster_id`、`secret`、`node_name`、`team_id`、`team_name`、`listen_host`（默认 `0.0.0.0`）、`listen_port`（默认 17890）、`advertise_host`、`hubs`（Worker 连的 Hub 地址列表）、`hub_peers`（多 Hub 对等，后续阶段使用）、`require_approval`、`heartbeat_sec`、`offline_sec`、`request_timeout_sec`、`export.chunk_size`（默认 6，钳 1..50）、`export.max_attempts`（默认 2，钳 1..5）、`export.request_timeout_sec`（默认 1800，钳 60..7200）。`secret` 至少 16 位、集群内所有节点一致；`getConfig`/`saveConfig` 不回传密钥，只回 `secret_set`，保存时留空或 `******` 表示不修改。节点间请求走 HMAC（时间戳 ±60s + nonce 120s 去重），管理接口只接受本机来源。
   - 状态目录：`state/cluster/node.json`（持久 node_id）、`service.json`（服务状态/监听/错误，GUI 与 RPC 读取）、`registry.json`（Hub 注册表/审批）、`peers.json`（Worker 最近一次 Hub 心跳与节点表）。

## 七、U 盘监听与调度规范（服务端指令驱动）

- **唯一监听者**：`app.py usb-agent` 常驻。Linux 为桌面用户的 systemd service，Windows 为登录计划任务；GUI 启动时只补拉一次。`state/usb-agent.lock` flock 保证单实例：GUI 补拉/`--once` 抢不到立即退出；systemd 服务设 `UVMP_USB_AGENT_WAIT_LOCK=1`，抢不到时等待接管（GUI 拉起的实例退出后服务立即接岗），服务 unit 为 `Restart=always` + `StartLimitIntervalSec=0`，不会因反复失败永久停在 failed。
- **集群服务同进程**：`usb-agent` 每轮 `ensure()` 按 config 启停 `toolkit/cluster` 的 HTTP 服务（Hub 注册表/心跳、Worker 主动连 Hub）；`--once` 不启动。集群线程与 U 盘消费互不阻塞，服务失败只写 `state/cluster/service.json` 的 `last_error`，不影响 U 盘指令。
- **事件源**：Linux netlink uevent（block `add`/`remove`）+ 兜底轮询（默认 15s，`usb.agent.poll_sec`/`mounted_poll_sec` 可调）；事件去抖 4s。**挂载只由“设备出现且未挂载”触发**：宽限期内每秒复查桌面是否已自动挂载，宽限到点仍未挂载才 `udisksctl mount`（一次 3 轮、间隔 5s），失败按 30s→300s 退避重试（不再等下一次拔出/插入）。轮询只做发现/消费，绝不反复 mount，避免频繁挂载把系统拖卡。
- **挂载状态机**：先等桌面自动挂载 10s；仍未挂载才 `udisksctl mount`，**一次尝试 3 轮（间隔 5s）**，失败按 30s→60s→120s→300s 退避重试（不再“等下次插拔”）。**挂载成功、观察到挂载点消失（服务端取件断开共享、设备节点仍留在被控机）、设备拔出、收到 udev 插拔事件都会复位重试状态**：KVM 取件时盘会短暂断开而设备仍在（日志“U盘已卸载”而非“已移除”），沿用“每插入周期只挂一次”会永久挡住后续挂载（udisks 不保证自动挂载兜底、也不保证 udev 事件）。`usb-agent --once`/页面检查可强制立即重试；**客户端从不主动卸载**；`state/usb.lock` 串行化扫描/挂载/执行/结果写入，GUI 手动检查也不会并发。
- **挂载点校验**：每个挂载点先 `stat`/`os.access` 验可读可写。断线残留（EIO）与 root 挂载（EACCES）只记录原因并跳过，不再误判成“U 盘断开”；同名卷标有多个可用挂载点时，优先含指令文件、其次挂载目录最新的那个。`udisksctl` 拒绝会翻译成可操作提示（polkit 规则缺失 / 缺少 exfat 支持 / 设备刚被切走）。
- **指令协议**：盘根 `{app}_cmd.json`；agent 认领为隐藏 `.running`，执行后先原子写 `{app}_result_<id>.json`，再删指令。崩在中间由下次挂载补写 `interrupted`；结果写盘失败落 `state/usb-agent/pending/`，下次挂载补写。指令/结果都只允许盘根，禁止路径穿越。指令文件读失败（EACCES/EIO）按 IO 错误保留指令、下轮重试，不得按“指令损坏”写失败结果并删除。
- **心跳**：每轮检查写 `state/usb-agent/heartbeat.json`（无 U 盘也写，含 pid/ts/device/mount/readonly/state/last_error/last_command）；GUI 树障/交跨/派车页的「后台监听」行与 `getUsbAgentStatus` 读它，`state/usb-agent.lock` 被占用即 `running=true`。
- **服务端调度**：服务端全局 U 盘会话锁串行；结果驱动等待统一为**单次窗口：指令下发后等满 10 分钟取回一次**（`usbcmd.Once(usbcmd.DefaultResultWait)`；派车 `WORKLOG_DISPATCH_CMD_WAIT_MINUTES` 可调），不再 60s/3m 多轮 collect——每次 collect 都要断开共享，反复插拔会让被控机 udisks 卡死；轮次结束（成功/超时）`defer usbcmd.RestoreShare` 把 U 盘复挂回被控机，失败也不再把盘留在非共享；指令 TTL = 等待窗口 + 5 分钟。客户端不再有 09:15/23:55 定时、夜间兜底或 `--if-due`；对应设备文件传输仅在服务端 mount→等待结果的窗口内停用，结果取回即恢复。
- **日志留存**：任务日志 `state/logs/<job>.log` 30 天（GUI「清除日志」跳过 `usb-agent.log`，避免删掉常驻 agent 正在写的文件后整天无日志）；`usb-agent.log` 1MB×5 轮转、30 天，并同时写 journald（systemd 单元设 `UVMP_AGENT_JOURNAL=1`，日志文件丢失也能 `journalctl -u uvmp-toolkit` 排障）；`state/usb-agent/journal.jsonl` 指令审计 30 天/最近 1000 行；U 盘结果文件服务端取走即删，未取走客户端 7 天清理；服务端每条指令/结果落 `intranet_sync_cmd`，按 30 天每日清理。
- **手动调试**：`usb-agent --once` 或页面「检查 U 盘指令」只跑本地一次；页面手动入口发现服务端指令时返回 `skipped=agent_owned` 并保留指令（唯一消费者是 agent，避免服务端等不到结果文件）。不得恢复为系统定时器多路轮询，也不要再新增 `maybeRun*` 驻留 RPC。

## 七之二、集群指令转发与班组同步（Phase 2）

服务端 U 盘指令可带 `target.node_id` / `cluster` 与 `params.team_id/team_name/file`。`usb_protocol.normalize_command` 保留这些字段；`usb_agent` 按 `cluster_service.route_command` 分三类：

- `local`：无 target 或 target 为本机 → 现有 `backend.handle_command(job, cmd, mount)`。
- `remote`：本机是 Hub 且 target 为其他已审批节点 → `relay_command` 通过 `POST /cluster/command` 转发。转发前 `replace` 的新表从 U 盘读为 base64 附件；目标节点写入 `state/cluster/inbox/<id>/` 后在同一进程用 `handle_command(job, cmd, staging)` 执行，返回结果与产物；Hub 校验文件名/大小/`id/app` 后把产物写回 U 盘根并写结果。
- `deny`：集群未启用/本机不是 Hub/集群标识不一致/目标离线 → 直接写失败结果，不空等服务端窗口。

约束：

- 远端转发硬超时 `min(8 分钟, expires_at - 30s)`，服务端单次 10 分钟窗口留余量；超时/目标离线/班组不一致/目标未配置表均由 Hub 写 `ok=false` 结果。
- 目标节点校验 `target.node_id` 为本机、`cluster` 与 `cluster.cluster_id` 一致（任一侧为空时兼容旧单机）、`params.team_id` 与 `cluster.team_id` 一致（任一侧为 0 时跳过）。
- 结果增加 `target/node/relayed_by`；`data.file` 改写为产物 basename。Hub 重启时 `_recover_running` 会先按 `.running` 里的指令向目标 `/cluster/command/<id>` 取回结果，取不到才写 `interrupted`。
- Hub 挂载 U 盘时在盘根写 `cluster_nodes.json`（已入网节点 + 本机 Hub、`home_hub`、`sync_tables`）；服务端在树障/交跨会话中读取，刷新班组绑定页缓存。
- 节点 `sync_tables` 由 `tree_sync.local_path` / `crossing_sync.local_path` 计算 `{team_id,configured,exists}`；节点班组 ID 在「集群」页填写，必须与服务端绑定班组一致。
- 远端执行使用本机 `JobManager` 与应用表；任务历史/日志落在目标节点。产物大小上限 32 MiB，命令请求体上限 48 MiB；部署时注意 U 盘剩余空间。

## 七之三、集群导出分片（pcd_export）

派车单/轨迹导出可在集群内分片：发起节点（任意 Hub/Worker，GUI 所在机）把单号按 `cluster.export.chunk_size` 切成连续分片，多个节点并发执行。发起节点勾选时与其他节点并行；未勾选时不参与分片，只在本机其他节点全部结束后兜底剩余分片。

- **节点就绪**：`node_info.export_ready`（SSO 凭据或 token、浏览器/Electron、当前查询/渲染并发）随心跳上报；发起节点只接受 `online && export_ready.ready` 的选中节点，未就绪原因直接返回 GUI。发起节点未被勾选时仅作为兜底，不要求先就绪；被勾选时与其他节点一样校验。
- **分发**：`POST /cluster/export/run`（HMAC，`/cluster/export/*` 已列入公开端点白名单），body 为 `{job_id, chunk:{id,items,attempts}, options:{export_pcd,export_track,calibrate_noon,cluster_width}, concurrency:{query_workers,render_workers}}`。目标节点用本机 `JobManager` 在 **同一常驻进程**调用 `pcd_export.backend.run_cluster`（分片模式只写 `逐单/`，不合并、不出报告），把产物打 zip + base64 返回；`result.json` 按 `job_id/chunk_id` 幂等落盘，重复请求直接复用。单分片 zip 上限 32 MiB（base64 后仍在 48 MiB 响应上限内）。
- **并发**：GUI 每个节点单独设置查询/渲染并发（1..16）；分片内的查询/渲染仍走原有两级并行，节点总并发由用户显式控制。分片大小是全局配置，不随 GUI 变化。
- **重试**：分片失败按 `max_attempts` 重派；重派使用**新的 chunk id**（避免目标节点幂等复用旧失败结果），优先避开失败节点；单个单号失败则按全局 seq 生成单号重试分片。发起的兜底分片在远端全部结束后执行，保证任务闭环；最终仍失败的单号写入清单备注。
- **汇总**：发起节点按全局 `seq` 汇总 `rows/not_found/noon_rows`，复制各分片产物到最终批次 `逐单/`，复用 `pcd_export.backend.finalize_cluster` 合并 PDF、按全局顺序重算 12 点前页码、写 `_清单.csv`、`_未找到.txt`、`_12点前结束行程.xlsx` 与 `manifest.json`。文件名/命名规则与单机完全一致。
- **状态/取消**：发起节点状态在 `state/cluster/jobs/<job_id>/state.json`（含 chunks/rows/files），运行中可由 `clusterGetExport` 轮询；`clusterCancelExport` 取消本机 Job 并向在途节点 `POST /cluster/export/cancel`，目标节点取消对应分片 Job。集群服务重启后可读取落盘状态，但在途任务不会自动恢复，需重新发起。
- **安全**：节点间 HMAC + 集群标识校验；管理端 `start/status/cancel` 仍只接受本机来源。节点只回传与请求分片匹配的文件名，发起节点只取 basename，防目录穿越。
- **验证**：`python -m unittest tests.test_cluster_export tests.test_cluster_service tests.test_cluster_protocol tests.test_cluster_registry -v` 覆盖分片、重试、汇总；真实多节点/大文件/取消仍需实机验证。

## 七之四、节点更新分发（Phase 4）

Hub 更新后可在「集群」页登记本机安装包并推送给已入网节点；节点只接收落盘并提示手动打开安装包，**不自动提权/静默安装**。

- **登记安装包**：`POST /cluster/admin/update/packages`（本机）传 `{path, platform, arch, version}`；服务计算 sha256/大小，写 `state/cluster/update_packages.json`。同一 sha 重复登记会更新元数据；平台/架构归一为 `linux|windows|darwin` 与 `amd64|arm64`。
- **自动匹配**：`POST /cluster/admin/update/push` 传 `{nodes:[node_id]}`；Hub 只处理已审批节点，按节点 `platform/arch` 选**最新登记**的匹配包；离线/无匹配包/地址无效逐节点记失败，不阻塞其他节点。仅发起 Hub 推送，不跨其他 Hub。
- **传输**：Hub 调目标节点 `POST /cluster/update/begin`（`update_id=sha256`、文件名、大小、sha、版本、平台/架构）→ 多次 `/cluster/update/chunk`（4 MiB/片 base64，48 MiB 请求上限）→ `/cluster/update/commit`。节点逐片落盘、校验总和 sha256，写 `state/cluster/updates/pending.json`；平台/架构与本机不一致直接拒绝。
- **手动安装**：节点「集群」页显示待安装卡片（版本/文件名/大小），点「打开安装包」由本机 GUI/RPC 进程调用 `platform_utils.open_path` 打开系统安装器；用户确认完成安装。无提示、不执行安装命令。待安装包在 `state/cluster/updates/<sha>/`，可重复打开。
- **任务与状态**：Hub 推送使用 `JobManager` 的 `cluster_update` 任务，`clusterGetUpdate(job_id)` 轮询日志/进度；`clusterCancelUpdate` 取消当前推送（不删除已落盘包）。RPC：`clusterListUpdatePackages` / `clusterAddUpdatePackage` / `clusterPushUpdate` / `clusterGetUpdate` / `clusterCancelUpdate` / `clusterGetPendingUpdate` / `clusterOpenPendingUpdate`。
- **安全**：节点间 HMAC + 集群标识；管理接口仅本机；文件名取 basename、更新目录固定；sha256 校验；无自动执行。更新包上限 2 GiB。
- **验证**：`python -m unittest tests.test_cluster_update tests.test_cluster_service tests.test_cluster_protocol tests.test_cluster_registry -v`；真实双节点跨平台/大包/安装器仍需实机验证。

## 八、平台兼容与离线依赖规范

1. 常规业务 Python 核心只准用标准库 + 既有纯 Python wheel；新依赖须 `py3-none-any` 且入 `offline_packages/`，**禁止需编译的原生模块**。唯一明确例外是课程自动学习（`course_autoplay`）：正式客户端收编 `playwright==1.62.0`、`greenlet`、`pyee`/`typing_extensions` 与对应平台 Node driver（按 Windows / 麒麟 amd64/arm64 分架构收编），构建参数 `--collect-all playwright --collect-all greenlet`；最终安装包离线安装后无需目标机 pip / `playwright install`，**禁止依赖目标机自行安装**。
2. 核心兼容 **Python 3.7+** 的源码模式（麒麟老系统 Python 兜底跑 CLI）；**打包核心统一内置 CPython 3.12**（astral python-build-standalone，glibc 2.17+/aarch64 均有，PyInstaller 6 自带 aarch64 bootloader）——所有设备安装包行为一致，不随设备 Python 漂移。历史坑：`unlink(missing_ok=)` 是 3.8+ API，buster py3.7 核心包曾因此崩掉官方渲染器。
3. Windows 上不直接调 Win32 API（ctypes 的 libffi 依赖在 PyInstaller/conda 下脆弱——已踩坑）；用 `powershell -NoProfile -Command ...` 子进程替代。
4. 前端依赖锁定 `desktop/package-lock.json`（入仓）；本机装 electron 二进制用 `ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/`。
5. 路径一律 `pathlib`（Python）/ `path.join`（JS）；禁止硬编码 `/media/lenovo/...` 等机器相关路径。
6. shell 脚本必须 LF 行尾；bat 用 CRLF；`.gitattributes` 已锁（含 debian 无扩展名维护脚本——electron 时代在 desktop/build/*.sh）。
7. **壳层原生依赖的唯一例外（题库搜题）**：`quiz_search` 的 OCR 需要原生推理库，无法遵守第 1 条（Python 核心仍零原生依赖，该应用 backend.py 仅为注册占位）。实现全部在壳层 `desktop/electron/quizsearch/`：`onnxruntime-node`（钉版本；CPU EP 无 Intel/AMD/ARM 厂商绑定，替代原嗖嗖搜题的 MKL 方案）+ PP-OCRv4 mobile ONNX 模型（随仓入 `models/`，SHA256 见 models/README.md），推理跑在 `worker_threads` 线程（不拉起新进程：个别麒麟环境 utilityProcess spawn 即死——已踩坑，v2.5.4 起改用线程）。打包：`electron-builder.yml` 把 `node_modules/onnxruntime-node(-common)` 与 `electron/quizsearch/**` 列入 asarUnpack，`build/prune-ort.cjs`（afterPack）按目标架构剪枝 ort 预编译库；CI linux-amd64/arm64 job 有 buster 容器 glibc ≤2.28 门禁。`onnxruntime-node` postinstall 在 linux/x64 会联网拉 CUDA 库——CI 一律 `ONNXRUNTIME_NODE_INSTALL_CUDA=skip`。另注意 `desktop/package.json` 中 vite 打包进 dist 的渲染层依赖（vue/tdesign/xlsx）一律放 devDependencies，放 dependencies 会被 electron-builder 重复收进 asar（曾致 asar 205MB）。
8. **Linux（麒麟/UKUI）悬浮窗与对话框的三条坑**（v2.5.2 踩坑记录）：
   - 悬浮框拖动/缩放：渲染层坐标全不可靠（screenX/movementX 在悬浮窗上合成输入恒为 0，真实环境亦丢值；pointer capture 在 X11 出窗断流；Windows `setSize` 缩小只生效一次——三连踩坑）——最终实现：渲染层只报「起/止」，位移由主进程 16ms 轮询 `screen.getCursorScreenPoint` 得出，缩放用 `setBounds`（非 setSize），收缩留 3px 余量让光标不越窗界，blur/pointercancel 兜底 dragEnd。回归用 `tools/drag_poll_test.cjs`（打桩光标）。另外推理线程在 asar 外运行，其依赖（onnxruntime-node 与 **onnxruntime-common**）必须全部 asarUnpack，漏一个即 Cannot find module（已踩坑，且 worker 的 exit 文案曾把真实错误覆盖成裸 code=1）。结果窗（result.html）复用同一套拖拽轮询：标题栏拖动移动、右下角柄缩放，位置与尺寸落盘 `settings.result`（x/y/w/h）下次开搜恢复；仅开一个扫描框时结果窗不分区（不显示框标），选项逐行排列。
   - UKUI 文件对话框扩展名过滤不可靠（xlsx 直接不显示）：`dialog:pickFile` 统一追加「所有文件」过滤器兜底。
   - 截屏裁剪**不用 `crop.getBitmap()`**：裁剪图的缓冲不是稠密 w×h×4（实测约 3 倍，行距继承原图），直接喂 OCR 读成斜纹垃圾、识别恒为空——整屏缩略图的 getBitmap 是稠密的，按行手工裁出稠密 BGRA（`_captureBox`）。回归：`tools/scan_e2e.cjs` 只断言回路响应不够（空文本也算响应），实采图片喂管线才算数。
   - 任务栏/应用中心图标两条根因：① X11 WM_CLASS 取 `Browser::GetName()`（Unicode 产品名匹配必失败，出齿轮占位）——`main.cjs` 在 linux 下 `app.setName('uvmp-toolkit')` 并 `setPath` 钉回 userData 原目录，desktop 文件 `StartupWMClass: uvmp-toolkit`；② 单文件 `linux.icon` 只装 1024 单尺寸——yml 不显式设 `linux.icon`，回退 `build/icons/` 目录全尺寸集合（`build/make-icons.cjs` 从 build/icon.png 生成）；`afterInstall.sh` 末尾刷 gtk 图标缓存。

## 八之二、浏览器运行时与并行导出（Python）

### 浏览器通道（两条，分开验）

1. **官方页面直出（轨迹）**：`official_track.CdpBrowser` 以 `--headless=new --no-sandbox --disable-dev-shm-usage --remote-debugging-port=0 --user-data-dir=<临时 profile>` 拉起用户所选或自动探测的浏览器，端口走 profile 的 `DevToolsActivePort` 通告（360ent/Edge 不输出 `DevTools listening on`，不能依赖 stdout 解析），随后用 WebSocket 直连 CDP。导出的每个渲染槽位使用独立临时 profile 与工作目录 `state/browser-workers/<job>/worker-N`，成功收尾清理，失败保留诊断。退出走 CDP `Browser.close` + 进程树兜底，取消经 `job.add_cancel_hook(pool.stop)` 统一关闭。
2. **PDF 包版打印**：`vehicle_export.html_to_pdf` 优先调用自带 Electron（`--print-to-pdf`，路径由壳经 `UVMP_ELECTRON` 注入），缺失时回退用户所选/自动探测浏览器。自带 Electron 只承担本地 HTML → PDF，不承担需要真实登录态的官方页面渲染。
3. 证书边界：导出专用浏览器实例带 `--ignore-certificate-errors`（仅该独立 profile 的临时实例；官方地图/派车系统在目标网络可能需要），course 模式不做证书豁免；不要据此放开主窗口或其他业务的 TLS 校验。若实测为 SM2/TLCP 握手失败仍须公司国密浏览器。
4. CDP 自检：设置页「环境自检」→「CDP 渲染自检」由 `toolkit/selftest.py::run_cdp` 执行，只打开 `data:text/html;base64` 本地页（零网络），五步验证导航/eval/新 tab/截图 PNG/printToPDF，产物写日志目录 `cdp-selftest.png` / `cdp-selftest.pdf`；无浏览器或链路失败明确报错，不静默跳过。对应单元测试 `uvmp-toolkit/tests/test_selftest_cdp.py` 用 fake 浏览器，不联网。

### 并行导出（pcd_export，默认值已定）

- 查询池默认 `order_export.query_workers=8`（钳 1..16）：`bounded_map` + `ThreadPoolExecutor`，每个线程租借独立 `UvmpClient`/`requests.Session`（共享同一 `Auth`，token 刷新在锁内串行）；查询原语仍是 `vehicle_export.py` 的 runCode 直查/日期兜底，不改接口语义。
- 渲染池默认 `order_export.render_workers=4`（钳 1..16）：`RendererPool` 每个槽位独占一个 client、一个懒启动的 `OfficialTrackRenderer` 与独立工作目录；派车单渲染阶段完整结束后才进入轨迹渲染阶段，阶段内多单并行。
- 主线程按输入顺序收集结果并更新 `rows`、日志与进度；worker 不并发改共享 rows。`manifest.json` 的 `has/get/put` 同一把锁，`put` 先写同目录临时文件再 `os.replace` 原子替换（Windows `PermissionError` 有限重试），重跑自动跳过已导单据。
- 取消/异常：任务开始前 `job.check_cancel()`；取消后取消未启动 future、关闭全部渲染器并拒绝再启动浏览器（`RendererPoolClosed`）；单条渲染失败隔离并重建该槽位，不阻塞其余单据。
- 该并发是 **Python 原编排上的线程并发**，不是 Go 实现移植；不得把查询/渲染语义写成 Go 或外部导出进程协议。

## 九之二、本机构建通道（GitHub Actions 额度耗尽时）

CI（公开仓 GitHub Actions）每次发版全链——服务端双架构构建 + 客户端三 job——约耗 100+ 分钟额度（Windows 双倍计），公开仓免费额度 2000 分钟/月。
额度耗尽时在本机出包：安装包与 CI 使用同一份 electron-builder.yml，本机还会额外留下不发布的绿色 zip/tar.gz。

| 目标                                          | 本机（Windows）可做？ | 说明                                                                                                                                                                                                                                                         |
| --------------------------------------------- | --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Windows 核心 + Setup exe + 绿色 zip（仅本机） | ✅                    | `powershell -File packaging/build_local.ps1`                                                                                                                                                                                                                 |
| 麒麟 deb/tar.gz（amd64/arm64；tar.gz 仅本机） | ⚠️ 半可               | electron-builder 跨平台组 deb 没问题，但 **linux 核心必须在 linux 上构建**（PyInstaller 不跨平台）；本机无 Docker/WSL 时：在麒麟机上跑 `packaging/build_on_device.sh` 产出核心目录，拷回后 `build_local.ps1 -LinuxCoreAmd64 <目录> [-LinuxCoreArm64 <目录>]` |

要点：

- **绿色 zip/tar.gz 只属本机通道**：供本机/离线分发使用，不上传 GitHub Release、不进入 CNB 取件；CI 正式发版仍只发布 3 件安装包。
- 本机构建走 npmmirror 镜像拉 electron/winCodeSign/nsis（脚本内置 `ELECTRON_MIRROR`；github.com 直连不通也能构建）。
- npmmirror 重定向 URL 带签名 → electron-builder 缓存目录名每次随机 → winCodeSign 里的 darwin 符号链接在非管理员 Windows 解不开 → 反复重试失败（已踩坑）。`build_local.ps1` 自动处理：预下载三个 7z 到 `packaging/.eb-binaries/`（不入库）+ 起 127.0.0.1:8899 静态服务让 URL 稳定，并给 `app-builder.exe` 打等长二进制补丁 `-snld`→`-snl-`（7-Zip 21.07 不认 -snld；-snl- 把符号链接落成普通文件，无需特权）。
- `build_on_device.sh` 离线构建：Python < 3.9 时只构建旧版兼容核心（离线装 PyInstaller 5.13，麒麟系统 python3.7；6.x 需 3.8+ 不可用），**课程自动学习不可用**；完整课程能力必须 Python 3.12 构建（正式 CI 与 `build_linux_container.sh` 已内置 CPython 3.12）。wheel 包需在能上网的机器上 `pip download` 预置（脚本头部有命令；完整构建另需 Python 3.12 对应平台的 pyinstaller、playwright==1.62.0 及传递依赖 wheel）。
- 若某版本只改了 Python 业务代码，linux 核心可直接复用上一版 release 包里的 `resources/core/` 目录（仅限核心代码零变更时）。

   - U盘指令 `Permission denied: '/media/root/GLKVM/tree_sync_cmd.json'`：U盘被 root 挂载，而当前进程（通常是 GUI/桌面用户）无权读取。先 `systemctl status uvmp-toolkit.service --no-pager` 确认 agent active，并检查 `findmnt` 的 `user_id` 是否为当前桌面用户；若为 root 属主，在无同步任务时 `sudo umount /media/root/GLKVM`，再以桌面用户 `udisksctl mount -b /dev/<设备>` 重新挂载（挂载点应变为 `/media/<用户>/GLKVM`）。服务端「已下发（待被控机取用）」只表示新表已写入 U 盘，不代表被控机已消费；以结果文件 `ok`/`error` 与内网表为准。
