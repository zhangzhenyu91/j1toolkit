# 内网工具箱开发指南

> 本文档是内网工具箱的架构说明与开发规范，面向后续接入更多内网应用的开发者与 AI 编码助手。
> 改动前请先读完第一、二章；新增应用按第五章示例执行；所有规则延续壹匣（j1toolkit）约定：简体中文注释、最小改动、密钥不入仓、交付完整代码无占位。

## 一、项目定位与架构

### 1.1 定位

内网工具箱是运行在**内网被控机**（Windows 10+；银河麒麟 V10 SP1 / 统信 UOS amd64/arm64，X11 会话）上的**原生桌面客户端**。当前主轨为 **Go + Fyne 全量重构**（全功能已实现，Windows 安装布局 GUI/CDP/OCR 门禁已通过）；旧 **Electron + Python** 轨保留回退、未退役未删除。

首批应用：

| 应用 id           | 名称     | 职责                                                                                                                   |
| ----------------- | -------- | ---------------------------------------------------------------------------------------------------------------------- |
| `quiz_search`     | 题库搜题 | 屏幕双扫描框实时 OCR 搜题（Go 化：`internal/quizsearch` + `internal/ocr` + 原生 overlay 悬浮窗，见 §八.6）             |
| `course_autoplay` | 学堂刷课 | 接管受控浏览器自动学习国网学堂课程：全分页扫描、断点续刷、暂停/切换培训班恢复（Go 化：chromedp 驱动，见 §4.6）         |
| `pcd_export`      | 轨迹导出 | 按派车单号清单（xlsx/文本）按序导出派车单/轨迹 PDF（Go 并行导出，见八之二）                                            |
| `tree_sync`       | 树障同步 | 按服务端经 U 盘下发的指令（tree_sync_cmd.json）同步树障统计表 xlsx：snapshot 上盘 / replace 回内网，23:55 夜间兜底上盘 |
| `crossing_sync`   | 交跨同步 | 同上（crossing_sync_cmd.json，契约同 tree_sync，独立指令文件/成功戳/config 段）                                        |
| `daily_sync`      | 派车同步 | 定时导出当日派车单 xlsx 写入 U 盘（GLKVM），供壹匣服务端取走                                                           |

### 1.2 技术选型（已定，勿擅自更换）

**Go + Fyne（GUI）+ core-go 单 module（全部业务）+ 宿主公司浏览器（360 企业浏览器 360ent 等）/ CDP；Electron 33 仅作可选 Chromium 回退运行时。**

- **core-go 单 Go module 包含全部业务**：`cmd/uvmp-toolkit`（Fyne GUI，CGO）/ `cmd/uvmp-core`（无头 CLI/RPC，CGO_ENABLED=0）/ `cmd/uvmp-export`（并行导出工作进程，兼容旧 stdin/stdout 协议，CGO_ENABLED=0）；业务在 `internal/`：apps（应用注册）、auth（SSO 国密）、browser、config、course（chromedp 刷课）、exporter（并行导出）、job、ocr（PP-OCRv4 ONNX）、overlay（原生悬浮窗）、platform、quizsearch（题库）、render（CDP 渲染池）、rpc、schedule、state、ui、usb、uvmpapi、xlsx
- **9 页全 Fyne**（`internal/ui/appshell`）：home / history / daily_sync / tree_sync / crossing_sync / pcd_export / quiz_search / course_autoplay / settings；页面常驻构造、切页 Show/Hide；UI 与业务唯一边界是 `ui.Backend`（`internal/ui`，CoreBackend 实现 + FakeBackend 冒烟）
- **普通同步 / 并行导出 / 课程 chromedp / OCR / 题库 / 原生 overlay 均 Go 化**：tree/crossing/daily 同步走 `internal/apps/{dailysync,tablesync}`；导出走 `internal/exporter` + `internal/render`；课程走 `internal/course`（chromedp，`driver_chromedp.go`）；OCR 走 `internal/ocr`（PP-OCRv4 mobile，yalue/onnxruntime_go 运行时加载 ORT 1.20.1 共享库，构建标签 `onnx`）；题库悬浮窗走 `internal/overlay`（Linux 纯 Go X11 线协议直连、Windows 原生宿主，CGO_ENABLED=0 亦可构建）
- **浏览器默认宿主自发现**（`internal/browser`）：显式 `render.chrome` → Windows 360ent（注册表 App Paths HKLM/HKCU → `C:\ProgramData\360ent\Application\360ent.exe` → PATH/常见目录）/ Linux `browser360ent-cn-stable` 优先 → 兼容 qaxbrowser / Chrome / Edge；**不自动探测、不下载旧 browser-runtime**。`browser-runtime/`（Electron 33 + 极小 JS 适配器）仅作显式 Electron 回退，默认不再内置
- 旧 **Electron+Python 轨仅保留源码回退参考，发版流水线已移除**：`desktop/`（Electron+Vue 壳）、`toolkit/`（Python 核心）、`course_autoplay_trial.py` 等源码不删不动；`UVMP_EXPORT_ENGINE=python` 对照路径仅旧轨存在
- 壳与核心经 **stdio JSON-RPC**（`uvmp-core rpc`，方法契约与旧 `toolkit/rpc.py` 一致）；历史教训：PyQt5 方案（v1.x）因 PyInstaller/Qt DLL 收集与 NSIS 手写脚本编码问题翻车，已废弃

### 1.3 架构图

```
uvmp-toolkit(.exe)（Fyne GUI，core-go/cmd/uvmp-toolkit，CGO，Linux 缺省 -tags onnx,x11（Windows 为 -tags onnx））
  ├─ internal/ui/appshell：9 页常驻页面 + 托盘/主题（政企蓝白 token）
  └─ ui.Backend（CoreBackend）——UI 与业务唯一边界（FakeBackend 供冒烟/演示）

uvmp-core(.exe)（core-go/cmd/uvmp-core，CGO_ENABLED=0，无头 CLI/RPC）
  ├─ selfcheck / rpc / daily-export / tree-sync / crossing-sync / order-export
  └─ internal/rpc：stdio JSON-RPC（与旧 toolkit/rpc.py 同方法契约，供旧壳回退/排障）

uvmp-export(.exe)（core-go/cmd/uvmp-export，CGO_ENABLED=0，兼容协议）
  ├─ stdin 首行请求 {config,params,codes} / {"command":"cancel"}；stdout 仅 NDJSON 事件
  ├─ internal/auth（SSO 国密登录 + 凭证管理）/ internal/uvmpapi（查询原语，查询池默认 4）
  └─ internal/render（CDP 渲染池默认 2，官方页面直出；浏览器 = 宿主 360ent 等，
      显式 Electron 回退才用 browser-runtime，见八之二）

core-go/internal/ 其余：apps / browser / config / course（chromedp）/ exporter / job /
  ocr（PP-OCRv4 ONNX）/ overlay（原生悬浮窗）/ platform / quizsearch / schedule / state / ui / usb / xlsx

browser-runtime/（可选 Electron 33 运行时 + app/{package.json,main.cjs} 极小 JS 启动适配器；
                 仅显式 Electron 回退时装配，默认不内置、不自动探测）
  └─ --uvmp-browser-mode=export（隐藏窗+批次临时 profile+回环桥+地图域名证书边界）
     --uvmp-browser-mode=course（可见窗+持久 profile+9222+单实例复用）
```

**分层铁律**：`internal/apps` 及一切业务包禁止依赖 GUI（无头环境要跑）；Fyne UI 只做展示与交互，业务语义只经 `ui.Backend`。

## 三、运行方式

```bash
# Fyne GUI（需 CGO + C 工具链，Linux 缺省 -tags onnx,x11（Windows 为 -tags onnx））
cd core-go && go run ./cmd/uvmp-toolkit

# 无头 CLI（定时器/排障场景；冻结版二进制用法相同）
uvmp-core selfcheck                     # 自检：加载全部应用后端
uvmp-core daily-export --if-due
uvmp-core order-export --xlsx 清单.xlsx --outdir ./output
uvmp-core tree-sync --tick | --nightly --if-due
uvmp-core crossing-sync --tick | --nightly --if-due
echo '{"id":1,"method":"ping"}' | uvmp-core rpc   # RPC 冒烟

# 冒烟（详见第十二节）
UVMP_FYNE_SMOKE=gui ./uvmp-toolkit      # 首帧真实渲染后退出 0
UVMP_FYNE_SMOKE=ocr ./uvmp-toolkit      # 安装相对布局 ONNX 推理自检
uvmp-export selftest                    # CDP 冒烟（data: 页零网络）
```

## 四、插件规范

### 4.1 应用 = 两处落点（Go 轨）

1. `core-go/internal/apps`：`apps.Register(&apps.App{ID, Name, Badge, Desc, Order, Schedule, Backend})` 静态注册（Go 编译期注册，替代旧 Python 扫描 `apps/*/app.json` 的动态加载）
2. `core-go/internal/ui/appshell/page_*.go`：界面页（并在 `appshell.buildPages()` 登记，9 页常驻 Show/Hide）

### 4.2 Backend 契约（`internal/apps/apps.go`）

```go
type Backend interface {
    Run(j *job.Job, params map[string]any) (map[string]any, error) // 必需
}
type StatusBackend  interface { Status(cfg map[string]any) (map[string]any, error) }        // 可选
type PreviewBackend interface { Preview(params map[string]any) (map[string]any, error) }     // 可选
type BrowserBackend interface { LaunchBrowser(cfg map[string]any) (map[string]any, error) }  // 可选
```

`Run` 内规范：`j.Log()` 逐行汇报；`j.SetProgress(cur, total, label)`；工作单元间 `j.CheckCancel()`；单条失败不阻塞整体；产出落用户目录，中间件成功后删除。**Backend 禁止依赖 GUI**（CLI/定时器无头环境没有 GUI）。

### 4.3 Fyne 页面规范

- UI 与业务只经 `ui.Backend`（`internal/ui/backend.go`：SystemAPI / ConfigAPI / AppAPI / TaskAPI / HistoryAPI / QuizAPI / CourseAPI / ScheduleAPI / EventAPI）；不把业务语义写进 UI 层；冒烟/演示用 `FakeBackend`
- 主题走 `appshell/theme.go`「政企蓝白」token（与壹匣双端同套：品牌蓝 #0E3DA8 / 页面底 #F5F7FA / 正文 #1D2129…），禁止自造色系
- 任务用 TaskAPI `RunJob`（事件回调 log/progress/done/error）；文件/目录选择用原生对话框（`appshell/dialogs.go`）；打开产物目录 `OpenPath`；`progressRow` 默认隐藏（空闲任务卡不占高度），任务 `Reset` 时显示、`Set` 更新进度
- 三项主应用为轨迹导出、题库搜题、学堂刷课；派车/树障/交跨同步默认收在「开发者工具」，首页与侧栏均可展开，搜索与统一历史不受折叠影响。普通用户只看业务参数与结论，原始错误和技术日志默认收起在「排错日志（供技术支持）/技术诊断」；失败/启动失败终态自动展开排错日志并滚动到所在页面滚动区的可见位置，成功/取消/暂停保持收起，完整日志支持复制、导出
- 收藏、最近打开及新任务非敏感参数快照仅存 Fyne Preferences（`shell_prefs.go`），不写业务 config/RPC；统一历史复用六个应用 `History`，回填经页面 `RestoreParams`，旧历史无快照不得猜测；单项/清空历史同步清理对应快照。`Ctrl+K` 打开工具搜索，`Ctrl+,` 打开设置，均为应用内快捷键而非系统全局热键
- 壳层采用一体式顶栏 + 细边框圆角工作台，不使用额外画布、系统标题栏或非客户区灰边。Windows 10 用 `SetWindowRgn` 裁切 12px 圆角，X11 用 Shape 扩展；最大化仅补 `WS_MAXIMIZEBOX` 能力标志，并监听 `WM_SIZE` 同步圆角，确保 Fyne 原生重排。页面切换 200ms、控件反馈 120ms，仅移动容器/透明层，不在每帧重排；`ShowAnimations=false` 时直接落位
- **壳层 token（勿另造）**：顶栏高 48、窗口按钮 44×48、品牌图标 20 + 文字起点 44；侧栏宽 200、导航项高 44 / 圆角 8 / 图标 12 / 内边距 12，激活态浅蓝底 + 品牌蓝 3px 标记；内容区常规最大宽 1080、最大化 1440，居中留白。卡片统一 12px 圆角、1px 发丝线、14px 内边距，卡片间距 12、列距 16（侧栏面板例外：上左/上右/下右为直角，仅左下 12px 圆角，由 `sidebarSurface` 实现；其余卡片继续四角统一 12px）；正文/次要/辅助三级文字色与成功/警告/危险语义色取 `theme.go`「政企蓝白」token，顶栏窗口控制 hover 用 `BlockBG`、关闭按钮 hover 用危险红，不新增第三套色板或圆角
- **窗口模式（常规/最大化）**：`Shell.setWindowMaximized` 在原生窗口最大化状态变化时通知全部九页的 `windowModePage.SetMaximized(bool)`；页面必须在构造期预建常规与最大化内容，切换只改对象显隐与容器 `Layout`（`pageCardLayout` / `pageGridLayout` / `pageSplitLayout`），不得重建页面、替换控件、清空未保存输入或进行中任务，不得在切换中调用 Backend；折叠分组保持用户状态，`SetMaximized` 不调用 `SetExpanded`。隐藏会承载按钮的次级容器必须走 `appTooltipScope` 的 `hideForShell/showForShell` 清理 tooltip；失败/启动失败终态由 `taskResult` 自动展开排错日志，成功/取消/暂停保持收起；失败日志与开发诊断入口不得被常规次级显隐永久隐藏。所有页面实现 `var _ windowModePage = (*pageXxx)(nil)` 编译期守卫
- **常规/最大化信息层级**：自动化布局测试直接以页面内容区 928×638（默认窗口 1160×780 扣除顶栏、页头、200px 侧栏与顶部 pageTopGap=12 后的估算值）与 668×458（最小窗口 900×600 时，同样已扣除 pageTopGap）作为视口，二者不等同于真实窗口像素；关键设置与执行入口允许经整页滚动到达，长内容必须能滚到底并回到顶部。最大化布局在内容宽度窄于断点时必须退化单列（`pageGridLayout.breakWidth`，派车/同步 940、设置 1080、历史 760），宽屏再恢复双列/四列；执行历史常规 2×2 不设断点，任何宽度都保持两列。状态卡标题统一「运行状态」：常规只显示两列紧凑状态（派车为到期 / U 盘位置，树障/交跨为文件检查 / U 盘），最大化只显示四行或五行完整 `statusKV`，两组必须互斥显隐；紧凑状态用 `GridWithColumns(2)` 等分列布局，长路径/长文案换行完整可读，禁止用 `hrowGrow` 把右侧文本挤到裁切。派车页常规为「紧凑状态 → 定时与 U 盘设置 → 立即执行/结果 → 排错日志」，四行完整状态与执行记录最大化显示；树障/交跨共用骨架，常规为「紧凑状态 → 同步设置 → 两种执行/结果」，五行完整状态与历史最大化显示；两页最大化均为左状态/设置、右执行/日志/历史双栏。执行历史保持固定筛选 + 列表视口、不新增整页滚动，常规筛选 2×2，最大化把同一组四个筛选控件重排为单行，不复制控件、不丢回调、不隐藏条件。设置页常规为搜索 + 分组（仅账号默认展开，其余默认收起并保留用户手动切换状态），最大化搜索卡整行 + 分组双列，不强制展开/收起，搜索命中、清空恢复、开发诊断、`appSelect` 与 Scope 行为保持不变；搜索快照只恢复搜索前的用户状态。首页常规为告警 → 三列常用入口（≥600px；<600px 单列）→ 主任务 → 题库/学堂 → 后台同步折叠入口，最近结果仅最大化右栏显示；PCD 常规左选单号/保存选项、右开始导出/结果/日志，单号明细/长说明/历史最大化显示，进度空闲隐藏；题库常规保留「查看答案」默认收起入口，最大化右列展示且保持用户展开状态，高级设置/技术诊断入口两态保留；学堂常规左紧凑状态/URL/选项、右开始学习/结果，完整状态/检查点/历史/技术详情最大化显示，登录学堂与保持前台说明、同步安全句常规常显。断点严格区分：`pageSplitLayout` 在内容宽度 <600 时把右列按顺序叠到左列下方；`pageGridLayout` 按各页 `breakWidth`（派车/同步 940、设置 1080、历史 760）在 668 最小内容宽度下退化为单列，两者不可混写；同步执行态在 928×638 下执行卡可能略低于首屏，按整页滚动可达验证，不撤销 pageTopGap
- 品牌区使用官方 Logo 与单一文本对象；全局正文/标题使用嵌入 Noto Sans SC Regular/Bold，日志与需要对齐的内容使用 JetBrains Maple Mono Regular（`appshell/fonts.go` + `assets/fonts/`，版本与 SHA256 见 `sources.json`），不依赖目标机 sans-serif/fontconfig；两份完整 OFL 随安装包 `licenses/` 分发。复选框统一 20px 方框与文字基线。首页仅一个滚动区，执行记录保留 224px 内层视口，避免嵌套滚动失效
- 启动 stderr 记录 `goos/goarch/fyne_gl_build/xdg_session_type/display/wayland_display`（`cmd/uvmp-toolkit/render_diag.go`），仅表示编译期 GL API 与进程会话环境；公开 Fyne API 不能可靠读取当前窗口 GPU renderer/vendor/version，不得据此声称硬件加速已验证

### 4.4 RPC 方法表（`internal/rpc/server.go`，与旧 `toolkit/rpc.py` 同契约）

`ping` / `getSystemInfo` / `getConfig` / `saveConfig(updates)` / `getApps`（每项含 `has_browser` 标记） /
`getAppStatus(app_id)` / `launchAppBrowser(app_id)` → 启动/复用受控浏览器（仅实现 `LaunchBrowser` 的应用可用；同步调用，不创建 Job） /
`preview(app_id, params)` / `runJob(app_id, params)` → `{job_id}` /
`cancelJob(job_id)` / `getJob(job_id)` / `getHistory(app_id)` / `openPath(path)` /
`getJobLog(job_id)` → `{text}` / `deleteHistory(app_id[, job_id])` → `{records, files, skipped}` / `clearLogs()` → `{removed, skipped}` / `getLogStats()` → `{dir, files, bytes}`
驻留调度（`schedule.driver=app` 时壳每 60s 调用，与 OS 定时器经 due_check driver 门闸互斥）：
`maybeRunDaily` → `{started, reason, job_id?}`（每日派车单同步到点判定，tree_sync/crossing_sync 夜间兜底同挂此调用） /
`maybeRunTreeSyncTick` → `{started, job_id?}` / `maybeRunCrossingSyncTick` → `{started, job_id?}`

事件（核心→壳主动推）：`job.log{job_id,line}`、`job.progress{job_id,current,total,label}`、`job.done{job_id,job}`、`core.exit{code}`。
新增方法 = server.go 方法表加一项并同步本节（旧轨 `toolkit/rpc.py` 加 `m_<名字>` 同名方法保持契约一致）。

> `uvmp-export` 自己的 stdin/stdout 进程协议不经 RPC（见八之二），`runJob('pcd_export', params)` 契约不变。
> `quiz_search` 的实时截屏/OCR/悬浮窗不适合 stdio RPC，不新增核心 RPC（Go 轨在 `internal/ui` 的 QuizAPI 内闭环；旧轨壳层 IPC `quizSearch:*` 仅回退轨）。

### 4.5 任务（Job）模型（`internal/job` + `internal/state`）

- `job.JobManager` 统一管：日志写 `state/logs/<job_id>.log`，结束写 `state/jobs/<id>.json` + `state/history/<app_id>.jsonl`（页面历史数据源）
- 内存有界回收：终态 Job 只保留最近若干个（`MaxTerminalJobs`，超出按 job_id 降序回收内存对象）；**只收内存对象，任务档案与日志文件不受影响**，`getJobLog` / `getHistory` 仍可查全部历史
- 日志清理/执行记录删除语义与旧轨一致（`clearLogs` / `deleteHistory`，app_id/job_id 正则校验防路径穿越）
- 状态机：pending → running → success / failed / cancelled；终态落定后触发 done 回调（RPC 事件时序正确性靠它，勿在业务 finally 里自行推 done）

### 4.6 课程自动学习（course_autoplay）应用要点

- **引擎 Go 化（chromedp）**：`internal/course`（runner/monitor/checkpoint/driver_chromedp），以 chromedp 驱动**宿主公司浏览器**的课程模式（可见窗口、持久 profile、调试端口 9222、同端口单实例复用，start_url 直接作为首窗地址，见八之二）；显式 Electron 回退（`browser_automation.electron_path` + `runtime_dir` 成对配置）沿用 browser-runtime 适配器；旧轨 `course_autoplay_trial.py`（Playwright）保留回退
- **可选后端契约 `LaunchBrowser(cfg)`**：实现它的应用才可被 RPC `launchAppBrowser({app_id})` 调用（`getApps` 以 `has_browser` 标记）。打开浏览器不是 Job、不产生任务档案；已有受控浏览器时按 CDP 端口探活复用，不重复启动
- **用户流程**：填启动网址（随 config.json 永久保存）并点「打开浏览器」，自动访问该网址 → 人工登录并打开任意同国网学堂页面契约的「课程设置」列表且置前台 → 勾选「仅扫描（不进入课程）」或点「开始学习」（主按钮只有开始学习）→ 运行中可点「暂停学习」；完成提醒以启动时模式为准（正式学习且本轮 `pending=0` 才弹窗）
- **暂停/检查点语义**：暂停立即中断当前等待并释放开始按钮；旧任务未终态时再次开始会等旧任务退出，不重叠运行。暂停只断开 CDP、关闭当前学习弹窗，不杀受控浏览器、不清登录态；回滚当次尝试、不记失败。检查点按 trainid/列表持久化到 `state/course-autoplay/checkpoints.json`（续刷页、真实失败次数、已处理数、跳过项及原因）；切培训班独立检查点，切回可恢复。完成一轮后 `active=false`，下次为新一轮。任务历史 `cancelled` 且 `result.paused=true` 显示「已暂停」；失败截图落 `state/logs/<job_id>_failure_*.png`
- **引擎能力保持**：多标签识别、全分页扫描、视频真实 `ended` 等待（拖动后每轮限 30 秒，超时重定位重拖，连续 3 轮失败交回单课重试）与学习记录上报确认、非视频课件加载、单课 3 次（`course_autoplay.max_attempts`）后跳过继续、末页后从第 1 页从头复核、刷新后直接跳回续刷页
- **配置**：`browser_automation{start_url 空=空白页、step_timeout=120、electron_path/runtime_dir 历史 Electron 回退成对可选}`、`course_autoplay{max_attempts=3}`（键位与旧轨 config 兼容；CDP 端口 course 模式固定 9222；默认宿主浏览器不需要 runtime_dir）

## 六、配置与密钥管理规范

1. 三层配置：**内置默认值 < config.ini（只读）< config.json（GUI 可写）**。新应用的可调项在 Go `internal/config` 默认值与 `config.example.json` / `packaging/fyne/config.initial.json` 同步。
2. config.json 写入后 **chmod 600**（Windows 无权限位自动跳过）；真实值**绝不入仓**。
3. 路径解析：环境变量 `UVMP_TOOLKIT_CONFIG` > 用户配置目录（`~/.config/uvmp-toolkit/config.json` / Windows `%APPDATA%\uvmp-toolkit\config.json`）> 源码 `toolkit/config.json`（旧轨遗留）。**Go 轨与旧轨共用同一份用户配置与状态镜像**（`~/.local/share/uvmp-toolkit` / `%LOCALAPPDATA%\uvmp-toolkit`），回退旧版可直接用；root 定时器经 unit 的 `Environment=` 指向同一份用户配置；deb postinst 播种 `config.initial.json`（**定时默认停用**，客户端填好凭据后启用）。
4. SSO 凭据解析顺序：config.json `sso.*` → config.ini `[auth]`。新应用不自行读密码，统一经 `internal/auth` / config 凭据解析；密码在 UI 留空 = 不修改。
5. 状态目录（`internal/state`）：linux `$XDG_DATA_HOME/uvmp-toolkit`，Windows `%LOCALAPPDATA%\uvmp-toolkit`。**root 定时器与桌面用户状态分离是语义特性**。
6. U盘挂载归属（Linux）：重装无需重新识别或绑定，始终按卷标发现设备。root 定时器只承担导出，`udisksctl mount` 优先经 `loginctl` 识别的本机活跃桌面用户执行，避免挂载到 `/run/media/root` 导致桌面用户无权打开；无活动会话时回退镜像状态目录属主。每轮及挂载后均重新读取 `lsblk` 真实挂载点；Windows 仍按卷标发现。
7. 导出相关配置（键位与旧轨兼容）：`order_export.query_workers=4`（钳 1..8）、`order_export.render_workers=2`（钳 1..4）、`render.builtin`（历史 Electron 回退开关，缺省按 false 处理且不再写入默认配置）、`render.ignore_certificate_errors=false`、`render.certificate_spki_pins=[]`；显式 `render.chrome` 优先（设置页手选），留空则统一自动检测宿主公司浏览器（360ent / qaxbrowser / Chrome / Edge，见八之二）。环境变量：`UVMP_EXPORT_BIN`（显式 uvmp-export）、`UVMP_BROWSER_BIN`（显式宿主浏览器，CI/门禁/排障；与 `UVMP_BROWSER_WORKER`/`UVMP_BROWSER_APP` 同时出现时按历史 Electron 回退处理，见八之二；`UVMP_EXPORT_ENGINE=python` 对照开关仅旧轨）。

## 七、调度规范（due-check 模式，勿改回固定 OnCalendar）

- OS 定时器只负责**高频唤醒**（每分钟，`Persistent=true` 补跑关机错过的 tick），业务时刻表在 config.json `schedule.time`。分钟级 tick 下失败重试受尝试间隔闸约束，见下。
- 判定逻辑（`internal/schedule.DueCheck`）：启用 且 今日无成功戳 且 当前时间 ≥ 配置时刻 且 距上次尝试 ≥10 分钟（`daily_export_attempt` 戳，防失败任务每分钟重跑高频打 SSO）→ 执行；放行后执行前 `MarkAttempt`，成功后 `MarkSuccess` 写戳。手动执行不受间隔闸约束。
- **GUI 与 OS driver 互斥**：`schedule.driver` 取值 `os`（默认，系统定时器执行）/ `app`（客户端驻留每 60s 调 `maybeRun*`）。两路经 `DueCheck` 的 driver 门闸互斥——配置只认一种执行方，**绝不双跑**。安装包默认接管 OS 定时（driver=os）：Windows 注册 5 个计划任务 `UVMP-Toolkit-{DailyExport,TreeSyncTick,TreeSyncNightly,CrossingSyncTick,CrossingSyncNightly}`（`run-uvmp.vbs` 隐藏窗口调 `uvmp-core.exe` 同名参数）；deb 装 `uvmp-toolkit.service/.timer`（5 条 ExecStart 命令链同口径）。与旧版任务名/单元名一致 = 升级原位替换而非双跑。
- 收益：客户端改时间**零权限**；跨平台同一套判定（linux timer / Windows schtasks 只是触发器）。
- 新定时应用复用 `schedule` 时换自己的戳名，不要共用 `daily_export`。

## 八、平台兼容与离线依赖规范（Go 轨）

1. **CGO 边界**：`uvmp-toolkit`（Fyne GUI）必须 CGO + C 工具链；`uvmp-core` / `uvmp-export` 一律 `CGO_ENABLED=0`；`internal/overlay` X11 实现为纯 Go 线协议（无 cgo）。**CGO 不交叉编译**：目标产物一律原生构建（arm64 用 ubuntu-24.04-arm 原生构建机 + arm64v8/debian:buster 容器）。
2. **Windows C 工具链二选一**：MSYS2 MINGW64（`mingw-w64-x86_64-gcc` + pkg-config；CI 用 `msys2/setup-msys2`）或便携 gcc（w64devkit，`packaging/.toolchain/w64devkit`，本机离线构建用，**不入仓**）。
3. **ONNX 标签**：ORT 实现 `internal/ocr/ort` 置于 `//go:build onnx` 之后（yalue/onnxruntime_go 为 CGO 包，已入 `core-go/go.mod`）；`build_fyne_core.*` Linux 缺省 `-tags onnx,x11`（Windows 为 `-tags onnx`） + CGO，`go vet/test` 仍默认标签（无 CGO 环境不受影响，缺省为 stub）。ORT 1.20.1 共享库放安装相对 `native/`，运行时加载、不做构建期链接；模型 `models/` 按可执行文件所在目录发现。
4. **运行时发现**：`models/`、`native/` 按可执行文件所在目录的**安装相对布局**发现（launcher 另注入 `LD_LIBRARY_PATH=native`）；`browser-runtime/` 仅历史 Electron 回退时存在，**不自动探测、不静默下载**；宿主浏览器由 `internal/browser` 按注册表/PATH/常见目录探测。
5. 路径一律 `path/filepath`；禁止硬编码机器相关路径。shell 脚本 LF 行尾；bat 用 CRLF；`.gitattributes` 已锁。
6. **Linux 悬浮窗/截屏边界**：`internal/overlay` 支持 X11（纯 Go）与 Windows 原生宿主；**Wayland 会话不支持截屏/置顶悬浮窗，明确报错不静默降级**，须换 X11 登录。
7. **旧 Electron/Python 轨的例外条款仅适用于回退轨**（未退役、改动该轨时才遵守）：课程 Playwright==1.62.0 收编（`--collect-all playwright`）、题库壳层 `onnxruntime-node` + asarUnpack、PyInstaller 内置 CPython 3.12、`desktop/` 前端依赖锁 devDependencies 等——**Go 轨无 Python/Playwright 依赖**，该「唯一原生例外」描述已过时，不得再往 Go 轨引申。旧轨踩坑记录（UKUI 对话框过滤、Electron 悬浮窗拖动轮询、getBitmap 裁剪稠密性、WM_CLASS/图标等）见 git 历史与旧版文档，仅回退轨维护时参照。

## 八之二、浏览器运行时与并行导出（宿主浏览器 / uvmp-export / 证书）

### 进程协议（固定，勿改）

`uvmp-export run`（stdin 首行请求 / stdout NDJSON）：

- stdin 首行 `{"config":<config 全量>,"params":<pcd_export 参数>,"codes":[{seq,code,date_hint}]}`，之后可收 `{"command":"cancel"}`；
- stdout 仅 NDJSON 事件：`log` / `progress` / `done{result}` / `error`；`done.result` 与 `apps.Backend.Run` 返回形状一致，**产物格式/命名不变（§十）**；
- 密码只经 stdin 请求体传入，不进命令行、不落日志（日志/进度/stderr 环形记录统一脱敏）；取消走 stdin 指令 + 宽限期后整树强杀。

### 并行模型（默认值已定）

- 查询池默认 `order_export.query_workers=4`（钳 1..8）：`internal/uvmpapi` 查询原语（runCode 直查失败自动按日期范围兜底，`lookback_days`），预取与渲染流水并行。
- 渲染池默认 `order_export.render_workers=2`（钳 1..4）：每个渲染 Worker 独占一个浏览器进程、一次只渲一单，独立 WorkDir `state/browser-workers/<批次>/worker-N`（成功整目录清理，失败保留诊断）。
- `manifest.json` 断点续传记录并发互斥 + 临时文件原子替换写入；批次重跑自动跳过已导单据。

### 宿主浏览器（默认）与 Electron 回退

`internal/browser` 统一探测并驱动宿主公司浏览器，导出 `internal/render`、课程 `internal/course`/`apps.course_autoplay`、设置页与 `getSystemInfo` 共用同一口径：

| 模式   | profile                  | 窗口                             | 调试端口                               | 用途                                      |
| ------ | ------------------------ | -------------------------------- | -------------------------------------- | ----------------------------------------- |
| export | 批次临时目录（用完即弃） | 对用户不可见（`--headless=new`） | 0（自动分配，DevToolsActivePort 通告） | 导出渲染（uvmp-export / internal/render） |
| course | 持久固定目录             | 可见                             | 9222                                   | 课程学习（internal/course chromedp 驱动） |

- 探测顺序：显式 `render.chrome`（config.json / config.ini）→ `UVMP_BROWSER_BIN`（CI/门禁/排障显式指定）→ Windows 360ent 注册表 App Paths（HKLM/HKCU）→ `C:\ProgramData\360ent\Application\360ent.exe` → PATH/常见目录 → Linux `browser360ent-cn-stable`（PATH 与 `/usr/bin`）→ 兼容 qaxbrowser / Google Chrome / Microsoft Edge。找不到给出可操作错误，**不下载任何浏览器**。
- Windows 注册表读取在 `internal/browser/host_windows.go`（`x/sys/windows/registry`，Windows 专属构建标签），其它平台 `host_other.go` 返回空；单测经 `Probe` 注入候选/查询，不触碰真实注册表。
- 导出渲染（`internal/render`）宿主路径由渲染 Worker 直接拉起浏览器（独立临时 profile、随机调试端口），就绪以 profile 的 `DevToolsActivePort` 通告为准，再用 WebSocket 连 CDP——Edge/360ent 实测不输出 `DevTools listening on`，不能依赖 chromedp 的 stdout 解析；进程退出走 CDP `Browser.close` + 进程树兜底。Electron 回退仍由 chromedp ExecAllocator 拉起。
- 课程模式（学时刷课 /「打开浏览器」）：持久 profile、可见窗口、9222、start_url 直接作为首窗位置参数；复用已有实例时经 CDP `PUT/GET /json/new?<url>` 打开启动网址；**不附任何 Electron 专属参数**。
- 历史 Electron 回退（`browser-runtime/`，`app/{package.json,main.cjs}`，`--uvmp-browser-mode=export|course` 双模式）仅在显式配置时启用：`render.builtin=true` + `UVMP_BROWSER_BIN`（导出/自检），或 `browser_automation.electron_path` + `runtime_dir`（课程）。CI/门禁脚本的 `UVMP_BROWSER_BIN` + `UVMP_BROWSER_WORKER` 组合也按该回退处理。回退模式保留回环桥（`cdp-worker-bridge.json`，port+token；Electron 缺失 `Page.printToPDF`/`Target.createTarget` 时经 `/print-to-pdf`、`/new-window` 兜底）；普通宿主 Chromium 不走桥。
- `uvmp-export selftest` 即 CDP 冒烟（本地 `data:` 页 + 截图 + PDF，零网络访问）。

### 浏览器选择与证书

1. 显式 `render.chrome`（config.json 用户手选，**国密/兼容回退**）优先：路径必须存在；宿主浏览器导出走 `--headless=new`。渲染器不可用必须报错引导用户在设置页选公司浏览器。
2. 否则默认（未开启 `render.builtin`，按 false 处理）自动检测宿主公司浏览器；`render.builtin=true` 为历史 Electron 回退，仅在注入 `UVMP_BROWSER_BIN` 时生效（未注入按宿主检测，兼容旧配置升级），**不自动探测、不下载**；缺浏览器明确失败。
3. 证书边界：export 模式未配置 pin 时，仅该专用渲染 profile 对 `map.sgcc.com.cn` 豁免证书校验（Electron 回退经 `session.setCertificateVerifyProc`，其他域名仍走 Chromium 默认验证）；配置 `render.certificate_spki_pins` 后改用 SPKI pin（`--ignore-certificate-errors-spki-list`），不再使用域名豁免。course 模式不做证书豁免。不默认开启全局 `--ignore-certificate-errors` / `--disable-web-security`；`render.ignore_certificate_errors` 仅供公司浏览器兼容回退或临时排障。若实测为 SM2/TLCP 握手失败仍须公司国密浏览器。
4. 实测边界（不冒充）：Windows 安装布局 GUI/CDP/OCR 门禁为**历史记录**（gate_smoke + install_smoke，旧口径），**不代表本轮宿主浏览器改造后的 NSIS 实装/门禁已实测通过**；真实 360ent 宿主、SSO 登录、思极地图真实轨迹页、麒麟实机、国网学堂真实刷课均待验。

## 九、CI 构建与打包约定（必读）

CI（公开仓根 `.github/workflows/release.yml`，客户端与后端同一条版本线 `release-vX.Y.Z` / `vX.Y.Z`，各 job 以 `defaults.run.working-directory: uvmp-toolkit` 进入本目录）。**Go+Fyne 单轨**：旧 Electron+Python `client-*` job 已移除，`fyne-windows` / `fyne-linux-amd64` / `fyne-linux-arm64` 是唯一正式客户端构建链。

- 触发：tag 发版默认构建并上传三件套；`workflow_dispatch` 填 `fyne_track=build` 可仅做门禁，`publish` 可附加便携 ZIP/tar.gz。
- 构建：`packaging/fyne/build_fyne_core.{ps1,sh}`（Linux 缺省 `-tags onnx,x11`（Windows 为 `-tags onnx`）；Windows CGO 用 MSYS2 MINGW64，本机可换便携 w64devkit gcc；linux 在 debian:buster **原生**容器，arm64 用 ubuntu-24.04-arm 原生构建机，**CGO 不交叉**）；`uvmp-export` 复用 `packaging/build_go_core.*`（CGO_ENABLED=0）。
- 装配：`assemble_onnx.*`（`native/` + `models/`）按 `packaging/fyne/assets/*.json` **固定版本 + SHA256 逐个校验**（清单只写实测值，禁止编造）；`assemble_deb.sh` / `assemble_nsis.ps1` 出安装包与绿色包。浏览器默认宿主公司浏览器（360ent 等），**安装包均不再随带 Electron**；`fetch_browser_runtime.*` 仅作可选历史回退装配。
- 门禁顺序：构建 → ONNX 装配（SHA256）→ deb/NSIS 装配（含包内脚本齐全性断言）→ `gate_smoke`（glibc/ldd 或 DLL 依赖 + GUI/CDP/OCR 冒烟）→ `install_smoke`（实装 → 安装布局 → OS 调度接管/同名替换 → launcher 实跑 → 卸载清理/配置保留）。任一失败即 job 失败。
- 版本来源：tag 构建传 `UVMP_FYNE_VERSION`；非 tag 回退 `uvmp-toolkit/version.json`（与 `desktop/package.json` 解耦）。
- 产物保留 `-fyne-` 中缀和 `.exe`/`.deb` 后缀（CNB 取件口径）；CNB 仅接受 Go+Fyne 三件套，旧 Electron+Python 附件直接判失败。便携 ZIP/tar.gz 不带 exe/deb 后缀，不进入 CNB 取件清单。

CNB 构建链说明：CNB 无 Windows 构建节点，Windows 客户端只在 GitHub Actions 构建；wine 跨构建已试验放弃；Gitee 因单附件 100MB 限制 + 跨境不稳已弃用。CNB 侧「上传 Release 附件」流水线从 GitHub Release 接力传 CNB Release（GitHub→国内大附件跨境上传不可靠——已踩坑）。下载入口在壹匣登录页推广区（CNB 公开仓 Releases 最新 tag 实时拼接）。

核心冻结约定（改动代码时必须保持成立）：

1. `uvmp-export` 与核心同目录装配（`UVMP_EXPORT_BIN` 可显式指定）；其 stdin/stdout 进程协议为固定契约（见八之二）。
2. 运行时资产（models / native）按安装相对布局发现；`browser-runtime/` 仅显式 Electron 回退时存在且不自动探测；装配清单 SHA256 不匹配即失败。

4. 打包资产文件名一律 ASCII（GitHub 资产名剥非 ASCII——已踩坑）。
5. **渲染唯一路径：官方页面直出**（PNG → 包版 PDF）。内置模板已删除且禁止加回；渲染器不可用必须报错引导用户在设置页选公司浏览器；dev.mock 联调占位勿用于生产。
6. 旧轨冻结约定（PyInstaller 收编、electron-builder files 覆盖范围、Electron 33 钉版、buster 基线 + CPython 3.12 等）**仅回退轨维护时适用**，见 git 历史。
