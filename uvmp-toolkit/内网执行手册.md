# 派车单导出脚本 · 内网执行手册（给 AI 助手）

> 你是内网运维助手。请**严格按本手册逐条执行**，遵守以下规则：
> 1. 每条命令单独执行，看到输出后再执行下一条，**不要跳步、不要合并命令**
> 2. **不要修改 `vehicle_export.py`**；除本手册明确指示外，不要编辑任何文件
> 3. 每个命令设置超时 300 秒；全程**不要使用 sudo**（本手册没有需要 sudo 的步骤）
> 4. 脚本运行类命令**最多重试 2 次**，失败就停下去收集诊断信息，避免账号被锁
> 5. 报告中**原样粘贴**命令输出（不要总结、不要省略、不要翻译），但**不要粘贴 config.ini 的内容**（里面有密码）
> 6. 所有路径含中文，命令中务必用引号包住

---

## 第 0 步：进入目录并检查环境

```bash
cd "/data/usershare/浏览器自动化/派车单导出"
python3 --version
which google-chrome || which chromium || which chromium-browser
ls vehicle_export.py config.ini
ls templates offline_packages
```

**预期输出**：
- Python 版本号 ≥ 3.7（如 `Python 3.7.x`）
- 一个浏览器路径（如 `/usr/bin/google-chrome`）
- 文件列表正常显示，没有 "No such file or directory"

**分支**：
- python3 不存在 → 停止，报告"python3 未安装"
- 浏览器找不到 → 记录此情况，继续往下（后面有专门处理）
- 文件缺失 → 停止，报告缺哪个文件

## 第 1 步：准备 Python 依赖（免 pip 方式）

```bash
cd "/data/usershare/浏览器自动化/派车单导出"
mkdir -p pylib
for f in offline_packages/*.whl; do python3 -m zipfile -e "$f" pylib/; done
```

**校验依赖可用**：

```bash
python3 -c "import sys; sys.path.insert(0,'pylib'); import requests, gmssl; print('deps ok')"
```

**预期输出**：`deps ok`

**分支**：报 ImportError → 停止，把错误原样报告。

## 第 2 步：确认登录配置已填写

```bash
grep -c "^username =." config.ini; grep -c "^password =." config.ini
```

**预期输出**：两个数字都是 `1`（表示 username/password 已填）。

**分支**：
- 任一为 `0` → 停止，报告"config.ini 的 [auth] username 或 password 未填写，请人工填写后重试"
- **不要**把 grep 到的具体密码内容写进报告

## 第 3 步：小范围冒烟测试（只导派车单，一周数据）

```bash
cd "/data/usershare/浏览器自动化/派车单导出"
python3 vehicle_export.py --auth sso --from 2026-09-01 --to 2026-09-07 --type pcd 2>&1 | tee run1.log
```

**成功的样子**（依次出现）：
```
登录成功：……
使用浏览器渲染 PDF：/usr/bin/google-chrome
派车单共 N 条（X 页）
派车单：共 N 单，已导出 0 单，本次待导出 N 单
[1/N] 派车单_A-PC-……pdf
……
派车单导出完成：成功 N / N
全部完成，输出目录：……
```

**成功则**：执行 `ls -la output/`，把输出发进报告，然后去【第 5 步】。

**失败分支**（对照处理）：

| 报错特征 | 处理 |
|---|---|
| `AuthError: 凭证校验失败（HTTP 401` | 去【第 6 步】收集诊断 |
| `preLogin/check 未返回 userTicket` | 把报错中"响应原文"之后的全部内容原样报告，停止 |
| `未找到 Chrome/Chromium 浏览器` | 把第 0 步 `which google-chrome` 的结果用文本编辑器填入 config.ini 的 `[render]` 下 `chrome =` 后面（如 `chrome = /usr/bin/google-chrome`），然后重跑本步 1 次 |
| `缺少 gmssl 库` / `缺少 requests 库` | 回到第 1 步重新执行并校验，再重跑本步 1 次 |
| `SSO 登录未获得 T` 或 `getUserAuth: isLogin=false` | 报告"账号密码可能被系统拒绝，需人工核对密码"，停止 |
| 其他 Python Traceback | 原样报告最后 30 行，停止 |

## 第 5 步：全量导出（整月）

> 仅当第 3 步成功后执行。

```bash
cd "/data/usershare/浏览器自动化/派车单导出"
python3 vehicle_export.py --auth sso --month 2026-09 2>&1 | tee run2.log
```

时间可能较长（每单约 1~2 秒）。中途失败没关系——重跑同一命令会自动跳过已导出的单据（断点续传）。

**完成后执行**：

```bash
ls output/ | wc -l
ls output/ | head -20
du -sh output/
```

把以上输出原样写进报告，任务结束。

## 第 6 步：401 诊断信息收集

> 仅当第 3 步报 401 时执行。目标是收集 3 份材料。

### 6.1 收集脚本报错全文

```bash
cat run1.log
```

把内容原样写入报告（其中包含 Token-Refresh 头、服务器响应体、请求 URL、计算出的签名）。

### 6.2 先重跑一次冒烟测试（收集 getUserAuth 字段信息）

> 新版脚本会在登录后打印 `getUserAuth 响应字段: …` 一行，用于判断 mtk 是否取到。

```bash
cd "/data/usershare/浏览器自动化/派车单导出"
python3 vehicle_export.py --auth sso --from 2026-09-01 --to 2026-09-07 --type pcd 2>&1 | tee run2.log
```

把 `run2.log` 全文写入报告（特别注意 `getUserAuth 响应字段:` 和 `!! 警告` 两行）。

### 6.3 运行签名校验工具（自动定位签名差异）

1. 在 Chrome 中登录派车系统（**保持这个浏览器会话不关**，下面两步都在同一个会话里做）
2. 进入 **运行管理 → 派车单管理**，点击一次 **查询**
3. F12 → Network → 找到带 `pcdmanager/?rnd=` 的 **GET** 请求（不是 OPTIONS）→ 右键 → **Copy → Copy as cURL**
4. 运行：

```bash
cd "/data/usershare/浏览器自动化/派车单导出"
python3 verify_sign.py
```

5. 按提示把 cURL 内容整段粘贴进去，单独一行输入 `EOF` 回车
6. 出现提示后，回到浏览器 F12 → **Console** 执行：
   ```js
   copy(JSON.stringify(cube.mtk))
   ```
   把结果粘贴进去回车
7. 工具会打印每个签名变体的比对结果。**把屏幕完整输出原样写入报告**（重点：哪一行带"与浏览器一致！"或"全部变体均不一致"）

> 注意：cURL 和 mtk 必须来自**同一个浏览器登录会话**。如果中途重新登录了浏览器，cURL 和 mtk 都要重新复制。

### 6.4 打包诊断材料

```bash
cd "/data/usershare/浏览器自动化/派车单导出"
ls -la run1.log run2.log
```

报告：`run1.log`、`run2.log` 两个日志 + 第 6.3 步 `verify_sign.py` 的完整屏幕输出，交由人工带出内网。
