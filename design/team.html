数据模型与迁移

  • 新表 sys_team：id / name 唯一 / sort / status / kvm_group_name（已废弃保留列，设备组与班组同名绑定）/ created_at；种子 = 检修一班（默认班组）+ 运维二班。
  • sys_user：新增 team_id（替代 team 文本列，旧列迁移后弃用不删）；role 扩为 admin / team_admin / user；ADMIN_USERNAME 恒为超管。
  • 出工日志：worklog_entry / vehicle / destination / member 加 team_id；字典唯一约束改为（班组 + 名称）。
  • 新表 worklog_tower：team_id / 电压等级 / 线路名称 / 杆塔号 / 经纬度；既有 tower-coords.json 迁入检修一班。
  • 迁移口径：全部既有数据（用户、日志、字典、杆塔、安全日记录）归入 检修一班；安全日 records.json 旧记录回填 team，docs 根目录散落 docx 移入 docs/检修一班/（保留双路径兜底）。
  • 员工调班：历史数据定格在原班组（记录带 team_id），新数据进新班组。

接口变更清单

  • 班组：GET/POST/PUT/DELETE /admin/teams（超管；DELETE 仅限无数据班组）。
  • 员工：GET /admin/users?team_id= 增加筛选；新建 / 编辑支持 team_id + role 三态（team_admin 必须有班组）。
  • 出工日志：全部业务接口按班组强制过滤（防按 id 越权）；超管以 ?team_id= 指定目标班组；/worklog/admin/* 字典接口放开为 超管 或 本班 team_admin。
  • 杆塔：GET /worklog/towers 按班组出数；新增 GET /worklog/towers/template（模板下载）与 POST /worklog/towers/import（xlsx 全量替换本班坐标）。
  • 安全日：/records 按班组过滤（超管可 ?team= 或全部）；下载 / 预览 / 删除校验记录班组归属。
  • KVM：/kvm/devices 按本班组绑定设备组过滤；回退时响应带 fallback: true 与来源班组名。
  • 依赖：新增 xlsx（SheetJS，纯 JS 无原生编译）用于导入解析与模板生成。

存储与路径规则

  • COS 照片：{COS_WORKLOG_PREFIX}{班组名}/{yyyy.MM.dd}/{entryId}-{ts}.jpg
  • COS 备注附件：{COS_WORKLOG_PREFIX}remark/{班组名}/{yyyy.MM.dd}/{entryId}-{ts}.{ext}
  • 安全日产物：{SAFEDAY_DATA_DIR}/docs/{班组名}/{date}.docx
  • 旧数据一律不搬迁 COS / 不动存量 key（库内已存全量 url / cos_key，天然兼容）；仅安全日 docs 根目录旧文件启动时移入默认班班子目录。

KVM 班组绑定与回退

  • 平台设备对象自带 deviceGroupName（现有设备卡片的班组标签即取自它），设备组与班组同名绑定（约定平台设备组名 = 班组名，无需单独设置，也无需数字 ID）。
  • 生效设备 = 当前员工平台可见设备中 deviceGroupName 命中本班组名的设备（服务端拉全量后按名称过滤，不走平台 groupId 参数）；组内 0 台 → 回退默认班组（检修一班）设备 + 提示横幅。
  • 组内一旦有设备（无论在线离线）即只显示本班组设备，回退自动解除。
  • 班组改名后，GLKVM 平台侧设备组需同步改名，否则触发回退提示。
  • 平台侧前提：员工平台账号需对「本班组组 + 回退组」均可见（平台授权设备组），否则列表为空。
  • 远程连接（PC）与文件传输（小程序）共用 /kvm/devices，同一口径。

出工成员同步 与 杆塔导入规则

  • 成员默认同步：班组内所有账号的昵称自动进入本班出工成员字典（启用、sort 追加），标记「账号同步」。
  • 触发点：新建员工 / 改昵称 / 调班组 / 停启用账号；只增不删——调出或停用账号 → 成员自动停用（保留历史引用）。
  • 手动增补：非账号人员（如外协）仍可手动添加 / 改名 / 停启用 / 排序；同班同名去重。
  • 杆塔导入：模板列固定「电压等级 / 线路名称 / 杆塔号 / 经度 / 纬度」；导入为本班组全量替换（先校验后落库，缺列行跳过并提示行数）；超管按当前切换班组导入。
  • 未分配班组：子应用统一空态「未分配班组，请联系管理员」；超管无班组时默认落第一个班组。

不在本次范围（确认项）

  • Call Me、水印添加不分班组（Call Me 会话本来就按用户隔离）。
  • 权限管理（应用授权）仍为超管专属，不开放给班组管理员；「按班组批量授权」暂不做。
  • 出工日志「仅看我」口径不变（按昵称匹配本班成员字典）。
  • 班组改名对出工 / 员工数据无感（team_id 关联），仅安全日记录与 docs 目录需级联（服务端自动处理）。
