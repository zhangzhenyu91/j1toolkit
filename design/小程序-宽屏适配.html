RESPONSIVE CONTRACT · REVIEW

一套尺寸契约，四种设备形态

断点只负责改变信息结构；从 600px 起，字体、图标、间距、导航与控件全部使用固定像素，不再随视口等比膨胀。颜色、圆角、权限和业务数据口径不因设备改变。

01 · 断点与版心

沿用项目已有的 600 / 900 / 1200px 三档，组件可以依据自身可用宽度继续增列，但不额外制造全局字号断点。

< 600px

手机 · 保持原体验

底部 Tab、五日日期条、FAB 与底部弹层。仅作为对照，不重做手机端。

600–899px

iPad 竖屏 · 紧凑单列

720–760px 可读版心；首页五项一列，Tab 收拢居中；弹层限宽。

900–1199px

iPad 横屏 · 双栏任务区

72px 紧凑导航；首页应用/通知分栏；日志 248px 筛选栏 + 主列。

≥ 1200px

PC · 侧栏工作台

200px 可折叠侧栏，版心最大约 1280px；超宽只增列和留白，不再放大。

02 · 固定尺寸与可读性

以下为宽屏设计目标值，实施时映射为 px / 语义变量，不在页面另造色板。
元素 设计值 规则
正文 13–14px / 1.6–1.75 长文限制可读列宽，三级文字颜色保持层级。
页面 / 板块标题 18–22px / 15–16px 不再出现随屏宽增长的巨型标题。
关键数据 20–24px / 700 数字使用 tabular-nums，四项统计不裁切。
导航 / 主按钮 56–60px / 40–44px 每页至多一个主按钮；点击热区不小于 44px。
卡片 / 控件 / 标签 12px / 8px / 4px 沿用既定圆角；警示信息块仍为直角。
页面留白 20–24px 卡片间距 14–22px，超宽屏不继续放大间距。

03 · 页面与组件映射

场景 宽屏布局 不变量
首页 紧凑深蓝问候区 + 完整数据条；应用主列、通知辅列。 应用权限、图标无底块、通知默认摘要。
出工日志 左月历筛选、右日志主列；主列充足时内容/照片双区。 日期状态色点、卡片信息顺序、全部操作权限。
记录型列表 卡片最小宽度允许时增为双列；复杂记录保持单列。 不为增列而压缩文字、热区或状态标签。
表单 / 详情 720–840px 可读宽度；短字段可双列，长文保持单列。 校验、键盘避让、加载/错误/空态不合并。
月历 / 表格 月历可常驻；表格自身横向滚动，不撑宽整页。 日期状态语义、表格表头与关键操作可达。
弹层 ≥900px 居中对话框；普通 560–640px，复杂表单 760–840px。 固定头、独立滚动体、固定脚；Esc 关闭与焦点归还。

04 · 后续实施验收清单

  • 600px 起不再依赖 rpx 自动放大；导航、间距、圆角和 TDesign 内部尺寸同步约束。
  • 首页统计、应用名称、通知标题无裁切；PC 底部不出现分散整屏的两枚巨型 Tab。
  • 日志工具栏不遮微信胶囊；左筛选与右日志均可达，长卡与照片不造成整页横向滚动。
  • 横竖屏切换保留当前日期、筛选、展开状态和表单草稿，不重拉无关业务数据。
  • 弹层下拉展开后仍能滚动到底；头部关闭与底部保存始终可见，背景不可误触。
  • 鼠标 hover、键盘焦点、Esc、减弱动态效果和深浅色均有明确表现。
  • 网盘、树障、交跨、题库等按内容选择增列或限宽，不机械套同一双栏。
  • 按定稿实施后，仍须进行微信开发者工具、PC 微信和 iPad 真机复核，不以浏览器稿替代真机验证。

本页与设备稿均为静态评审材料；示例人物、车牌、线路与数据均已脱敏，不连接后端，不执行业务操作。
