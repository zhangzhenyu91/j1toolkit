01预检与冲突判定顺序
  • 先全量预检再执行：非法名 → 名称未变化 → 目标互撞 → 磁盘已有同名 → 仅大小写 → 循环改名。
  • 目标比较按 大小写不敏感（Windows 兼容口径），同一批目标重复即判互撞。
  • 校验 Windows 保留名与 \ / : * ? " < > |，Linux 上同样不生成这些名称。
  • 冲突默认跳过并写入结果原因；切换「自动追加序号」只改冲突项，非法名仍需人工修改。
02执行、取消与不覆盖
  • 两阶段提交：互换改名（a→b / b→a）与同批目标占用先改临时名，再落到目标名，避免 互相覆盖；仅大小写变化同样走临时名。本功能只改名称、不移动位置。
  • 磁盘同名只在预检中标记，没有覆盖代码路径；目标已存在即跳过或追加序号。
  • 取消立即停止后续项；已完成项保留新名，未处理项保持原名，结果清单标注「未执行」；预检已判为不改名的项单独标注「未变化」。
  • 不做撤销栈，也没有「回收站式回滚」；确认弹层是唯一防误入口。
03交互、边界与无障碍
  • 窗口沿用主客户端默认 1160×780、最小 960×620；侧栏固定 200px 不折叠，960 下规则列收窄至 268px，列表与原因仍完整可见。
  • 所有按钮 type="button"，焦点环统一；弹层 role=dialog、Esc 关闭、Tab 圈定与焦点归还。
  • 全页唯一主按钮固定为预览态的「执行重命名」；确认弹层的「确认重命名」是同一动作的二次确认。进度态只有「取消」，结果态用次按钮「导出清单 / 完成」。
  • 数字与时刻 tabular-nums；prefers-reduced-motion 下关闭全部入场与过渡。
04插件接入点（仅设计说明）
  • 插件 id batch_rename：声明落 toolkit/apps/batch_rename/app.json（id / name / badge / desc / order）， 业务后端落 toolkit/apps/batch_rename/backend.py。
  • 界面落 desktop/src/pages/BatchRenamePage.vue，在 App.vue 的 PAGE_MAP 登记 batch_rename: BatchRenamePage，并在 lib/navigation.mjs 的 NAV_ITEMS / GROUPS 加一项（business: true 后才进最近使用与收藏）。
  • 执行沿用既有模式：runJob('batch_rename', params, {onLog, onProgress, onDone, onError}) 拿进度与取消；结果区复用 components/TaskResult.vue，历史区复用 components/HistoryCard.vue，参数回填走 lib/restore-params.mjs（只回填、不自动执行）。
  • 预检放在 backend.py 的 preview(params)：非法名 / 互撞 / 磁盘同名 / 仅大小写 / 循环都在提交前算完，前端只渲染；run() 内逐项 job.log() + job.set_progress()，单元间 job.check_cancel()。
  • 本稿只交付界面设计，不创建上述产品文件、不改插件注册器与打包脚本。
